# Component

## Назначение

`Component` — базовая модель компонента. Компонент описывается моделью данных: экран — дерево моделей, а платформы
(Android, iOS) и Figma отрисовывают модели. Модели создаются как в коде приложений, так и на сервере, поэтому содержат
только данные, без кода отрисовки.

Каждый компонент содержит поля базовой модели. Модель дополняется по мере согласования полей
(`specifications/component-model.md`).

## Состав

| Файл             | Роль                                     |
|------------------|------------------------------------------|
| `Component.json` | Публичный контракт: поля базовой модели. |

## Варианты

| Поле     | Тип                       | Назначение                                                            |
|----------|---------------------------|-----------------------------------------------------------------------|
| `layout` | `Layout` (`core/layout`)  | Размеры и положение компонента внутри родителя                        |
| `id`     | `string`, необязательное  | UI-тесты, источник событий, ключ элемента в списках, аналитика        |

Ожидаемая модель на Kotlin:

```kotlin
interface Component {
    val id: String? = null

    val layout: Layout
}
```

Отрисовка модели генерируется для платформы отдельно и в модель не входит.

## Рекомендации по использованию

- Не используйте `Component` напрямую: он задаёт общие поля для всех компонентов.
- Задавайте `id` стабильными осмысленными строками (например, `checkout.payButton`), а не случайными: они
  используются в тестах, аналитике и ключах списков.
- `id` уникален в пределах дерева модели (экрана). Контракт этого не проверяет; проверка выполняется валидатором
  деревьев и генератором в отладочной сборке.

## Ограничения и открытые вопросы

- Механизм расширения базовой модели (`extends`) в спецификации пока не определён: сейчас `Component` — обычный объект.
- Остальные поля базовой модели обсуждаются.
