# Component

## Назначение

`Component` — базовая модель компонента. Компонент описывается моделью данных: экран — дерево моделей, а платформы
(Android, iOS) и Figma отрисовывают модели. Модели создаются как в коде приложений, так и на сервере, поэтому содержат
только данные, без кода отрисовки.

Каждый компонент содержит поля базовой модели. Модель дополняется по мере согласования полей
(`specifications/component-model.md`).

## Состав

| Файл                            | Роль                                                             |
|---------------------------------|------------------------------------------------------------------|
| `Component.json`                | Публичный контракт: поля базовой модели.                         |
| `ComponentIndicator.json`       | Индикатор: угол, содержимое, зазор выреза.                       |
| `ComponentIndicatorAnchor.json` | Угол носителя: `topStart`, `topEnd`, `bottomStart`, `bottomEnd`. |

## Варианты

| Поле         | Тип                                           | Назначение                                                     |
|--------------|-----------------------------------------------|----------------------------------------------------------------|
| `id`         | `string`, необязательное                      | UI-тесты, источник событий, ключ элемента в списках, аналитика |
| `layout`     | `Layout` (`core/layout`)                      | Размеры и положение компонента внутри родителя                 |
| `padding`    | `Padding` (`core/padding`)                    | Внутренние отступы корня компонента                            |
| `appearance` | `Appearance` (`core/appearance`)              | Оформление корня компонента по состояниям                      |
| `indicators` | массив `ComponentIndicator`, необязательное   | Индикаторы у углов формы с вырезом                             |
| `events`     | набор `Event` (`core/event`), необязательное  | События и данные о том, что нужно сделать                      |

Ожидаемая модель на Kotlin:

```kotlin
interface Component {
    val id: String?

    val layout: Layout
    val padding: Padding
    val appearance: Appearance
    val indicators: List<ComponentIndicator>?
    val events: Set<Event>?
}

data class ComponentIndicator(
    val anchor: ComponentIndicatorAnchor,
    val content: Component,
    val gap: Spacing? = null,
)

enum class ComponentIndicatorAnchor { TopStart, TopEnd, BottomStart, BottomEnd }
```

Отрисовка модели генерируется для платформы отдельно и в модель не входит.

### Индикаторы

Индикатор — маленький компонент у угла носителя: точка «в сети» на аватаре, счётчик на символе вкладки, галочка на
фото. Индикатор принадлежит носителю, а не контейнеру: носитель сам вырезает его из своей формы с зазором, сквозь
который видно то, что лежит под носителем.

```
        ┌─────────┐
       ╱  фото     ╲
      │             │
      │           ╭───╮      ← центр индикатора — на середине дуги угла,
       ╲         │ ● │╱        носитель вырезан по кольцу шириной gap,
        └────────╰───╯         раскладка видит только размер носителя
```

1. **Якорь.** Центр индикатора ставится в точку угла формы носителя: у прямого угла — в вершину, у скруглённого — на
   середину дуги (под 45°). Точка на круглом аватаре садится на окружность. Смещения от этой точки нет.
2. **Содержимое** — любой компонент. Размер задаёт его собственный `layout`: `hug` или `fixed`; `fill` не имеет
   смысла, растягиваться не к чему. `position` содержимого не используется.
3. **Вырез.** Форма выреза — форма индикатора (его размер и `cornerRadius` показанного состояния), расширенная на
   `gap` во все стороны. Без `gap` выреза нет: индикатор просто лежит поверх.
4. **Что вырезается:** вся отрисовка носителя — фон, содержимое, наложение и обводка — независимо от `clip`.
5. **Раскладка индикатор не учитывает.** Размер носителя прежний, индикатор рисуется поверх носителя и может выступать
   за его границы. Родитель с `clip` выступ обрежет.
6. **Один индикатор на угол:** индикаторы в одном углу перекрылись бы. Порядок массива — порядок слоёв.
7. **Нажатие** — собственные `events` содержимого индикатора. Нажатие на вырез не доходит до носителя.

| Платформа | Носитель                                                                    | Индикатор                                                  |
|-----------|-----------------------------------------------------------------------------|------------------------------------------------------------|
| Compose   | `drawWithContent { clipPath(cutout, ClipOp.Difference) { drawContent() } }` | в общем `Box`: `align` и `offset`, размер `Box` — носителя |
| SwiftUI   | `.mask { Rectangle().overlay { cutout.blendMode(.destinationOut) } }`       | `.overlay(alignment:) { … .offset(…) }`                    |
| Figma     | группа с маской «форма носителя минус вырезы» во фрейме размером с носитель | над группой с маской, вне её                               |

## Рекомендации по использованию

- Не используйте `Component` напрямую: он задаёт общие поля для всех компонентов.
- Задавайте `id` стабильными осмысленными строками (например, `checkout.payButton`), а не случайными: они
  используются в тестах, аналитике и ключах списков.
- Значения `padding` по умолчанию задаёт каждый компонент по дизайну. Переопределяйте отступы в основном у
  контейнеров: ручная подстройка отступов у остальных компонентов нарушает единообразие интерфейса.
- Индикатор задавайте маленьким и контрастным к тому, что под носителем; зазор — `xs2` или `xs`.
- Не используйте индикатор для содержимого, которое должно влиять на раскладку: подписи под аватаром и кнопки рядом
  — дети контейнера.
- `id` уникален в пределах дерева модели (экрана). Контракт этого не проверяет; проверка выполняется валидатором
  деревьев и генератором в отладочной сборке.

## Ограничения и открытые вопросы

- Компоненты наследуют базовую модель полем `extends` (`schema-format.md`, раздел 5.2). Ссылка на `Component` в
  свойстве означает «любой компонент».
- Остальные поля базовой модели обсуждаются.
- Тень носителя может быть видна в зазоре выреза: нужно ли резать и тень, проверяется на платформах.
- `fill` у содержимого индикатора и повтор угла валидатор пока не проверяет (#37).
- Индикаторы в библиотеке Figma (свойства Figma-компонентов) — вместе с проектированием конкретных носителей.
