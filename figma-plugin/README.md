# Плагин Figma

Строит в Figma библиотеку и документацию дизайн-системы из набора данных (`specifications/bundle-format.md`). Задачи
плагина — эпик этапа 1 в `ROADMAP.md`. Сейчас плагин загружает набор с GitHub Pages или открывает файл, проверяет
версию формата и показывает сводку с источником набора (`bundle-format.md`, разделы 3.11 и 6);
по кнопке «Построить foundation» создаёт или обновляет на месте коллекции переменных, текстовые стили, стили эффектов и
компоненты символов (`figma-mapping.md`, раздел 3.1); по кнопке «Отрисовать примеры» рисует модели из `samples/` на
странице `Samples` (раздел 10), а по кнопке «Отрисовать экраны» — демо-экраны из `screens/` на странице `Screens`
(`bundle-format.md`, раздел 3.9). Каждая операция заканчивается отчётом.

## Сборка

Нужен Node из `.nvmrc`.

```sh
python3 tools/bundle.py          # из корня репозитория: набор в build/bundle.json (для ветки задачи)
cd figma-plugin
npm ci
npm run build                    # dist/code.js и dist/ui.html
npm run typecheck
```

`npm run watch` пересобирает плагин при изменении исходников.

## Запуск в Figma

1. В Figma Desktop: **Plugins → Development → Import plugin from manifest…** и выберите `figma-plugin/manifest.json`.
2. Запустите плагин **UI Design System** и нажмите «Загрузить с GitHub» — набор из `dev`, который CI публикует на
   GitHub Pages после каждого merge. Набор ветки задачи до merge открывается кнопкой «Открыть файл…»
   (`build/bundle.json`). Поле «Адрес набора» меняет адрес загрузки и запоминается; пустое поле — адрес по
   умолчанию. Строка «Источник» в сводке показывает ветку, коммит и время коммита набора.
   Затем нажмите «Построить foundation».
   Коллекциям с двумя режимами (`light`, `dark`) нужен платный тариф Figma.
3. Нажмите «Отрисовать примеры». Тёмный режим проверяется переключением режима коллекций у страницы `Samples`.
4. Нажмите «Построить компоненты», затем «Отрисовать экраны»: вложенные компоненты экранов — экземпляры со страницы
   `Components`. Кнопки «Построить компоненты» и «Отрисовать примеры» страницу `Screens` не трогают, поэтому экран
   переживает повторный импорт с прежними экземплярами.

## Устройство

| Файл                   | Роль                                                                    |
|------------------------|-------------------------------------------------------------------------|
| `src/code.ts`          | Основной поток: доступ к документу Figma, хранит открытый набор.        |
| `src/ui.ts`            | Окно плагина: загрузка набора с GitHub или из файла, сводка, отчёт.     |
| `src/ui.html`          | Разметка окна; сборка встраивает в неё скрипт окна.                     |
| `src/bundle.ts`        | Типы набора по `bundle-format.md` и проверка поддерживаемой версии.     |
| `src/messages.ts`      | Сообщения между окном и основным потоком.                               |
| `src/foundation.ts`    | Построение foundation: переменные, стили, символы, удаление устаревших. |
| `src/render.ts`        | Ядро отрисовки модели в режиме тела; величины foundation в файле.       |
| `src/samples.ts`       | Страницы `Samples` и `Screens`: карточки примеров и демо-экранов.       |
| `src/documentation.ts` | Страницы документации: `Overview`, foundation, core и компоненты.       |
| `src/ids.ts`           | Идентификаторы объектов Figma и общие преобразования.                   |
| `src/report.ts`        | Отчёт: счётчики по видам объектов и предупреждения.                     |
| `build.mjs`            | Сборка esbuild.                                                         |

Основной поток и окно проверяются разными конфигурациями TypeScript (`tsconfig.json` и `tsconfig.ui.json`): типы
Figma и DOM несовместимы в одной программе. Типы набора пишутся вручную и меняются вместе с `bundle-format.md`;
поддерживаемая версия — `SUPPORTED_FORMAT` в `src/bundle.ts`.
