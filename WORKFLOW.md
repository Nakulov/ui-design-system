# Как мы работаем

Памятка: что сказать Claude и что запустить самому. Подробности — в скиллах `.claude/skills/` и в README.

## Цикл задачи

| Шаг       | Что сказать                                         | Что происходит                                                                                    |
|-----------|-----------------------------------------------------|---------------------------------------------------------------------------------------------------|
| Груминг   | «давай погрумим …», «обсудим задачу …», «заведи задачу …» | Скилл `groom`: концепция → решения по одному → черновик задачи → после «ок» задача на доске в Groomed |
| Сброс     | `/clear`                                            | После груминга                                                                                    |
| Работа    | «берём в работу #N»                                 | Скилл `take`: ветка `task/<N>-…` от `dev`, In progress, изменения, проверка                       |
| Figma     | открыть плагин, отрисовать, сказать «отрисовал»     | Claude проверяет через MCP структуру, потом скриншоты; затем смотрите вы                          |
| Коммит    | «коммить»                                           | Только после вашего согласия; затем PR в `dev`, In review                                         |
| Слияние   | сливаете сами (squash), говорите «слил»             | Claude переключается на `dev` и обновляет его                                                     |
| Сброс     | `/clear`                                            | После PR                                                                                          |

Посреди работы не сбрасываем: договорённости, не записанные в задачу или память, теряются.

## Полезные слова

- **«закругляемся»** — Claude записывает незаписанное: решения в задачу, план в заметку «текущая работа» в памяти — и
  одной строкой говорит, где что лежит. Говорите перед `/clear` или перед уходом.
- **Новая сессия** — `groom` и `take` первым шагом читают заметку «текущая работа», состояние ветки и задачу с
  комментариями; если ветка задачи уже есть, работа продолжается в ней.
- **Проектирование контракта** — скилл `contract-authoring`: API атомов, типов и компонентов, JSON-контракты по
  спецификации. Его используют `groom` и `take`.
- Темы, всплывшие по ходу, Claude предлагает завести отдельно в Backlog — сами в задачу не попадают.

## Доска

[UI Design System](https://github.com/users/Nakulov/projects/8): Backlog → Groomed → In progress → In review → Done.

```sh
tools/board.sh status <N> groomed              # backlog, groomed, in-progress, in-review, done
tools/board.sh issue "<заголовок>" <метка> body.md   # печатает номер
tools/board.sh sub <эпик> <N>
```

Метки: `component`, `foundation`, `spec`, `process`, `epic`. Этапы — вехи из `ROADMAP.md`.

## Команды репозитория

```sh
python3 -m pip install -r tools/requirements.txt   # один раз
python3 tools/sync.py                              # после правки контрактов и примеров: min/max, README, IDE
python3 tools/validate.py --base origin/dev        # проверка, как в PR
python3 tools/validate_model.py <файл>             # проверить одну модель по контракту
python3 tools/bundle.py                            # набор для плагина: build/bundle.json
cd figma-plugin && npm ci && npm run build         # плагин: dist/
```

## Проверка в Figma

1. Figma Desktop → **Plugins → Development → UI Design System** (первый раз: Import plugin from manifest… →
   `figma-plugin/manifest.json`).
2. Открыть `build/bundle.json` → «Построить foundation» → «Отрисовать примеры».
3. Сказать Claude «отрисовал»; после его проверки — посмотреть самим и подтвердить.
