# Глоссарий

Термины дизайн-системы, которые встречаются больше чем в одном месте: в двух спецификациях, в спецификации и скилле,
в спецификации и README. Источник правды — спецификация: здесь одна строка определения, чтобы отличить понятие от
соседних, и ссылка на раздел. Определение пишется здесь, только если в спецификации его нет.

## Правила

1. У слова одно основное значение. Другие значения пишутся только с уточнением; строка термина говорит, с каким.
2. Новое понятие или новое значение слова добавляется сюда в том же PR, где появляется в спецификации.
3. Локальные имена одного раздела (`historyRow`, `releaseRow`) сюда не входят.

## Контракты и значения

| Термин | Определение | В JSON / Figma | Где подробно | Например |
|---|---|---|---|---|
| **сущность** | Единица хранения: каталог со всем, что к ней относится, — главным контрактом, README, журналом изменений, образцами. | `contracts/<слой>/<сущность>/` | `schema-format.md`, 11.1 | `contracts/components/text/` |
| **слой контрактов** | Уровень каталога `contracts/`: `foundation`, `core` или `components`. Без уточнения «слой» — слой Figma. Пишется «слой контрактов» или «слой `core`»; шаблон `<слой>/<сущность>/<Имя>` остаётся. | `foundation`, `core`, `components` | `schema-format.md`, 11.1 | слой `components` |
| **контракт** | JSON-описание типа: имя, тип, свойства или варианты, статусы платформ. Главный контракт сущности публичный, вспомогательные определения лежат в `definitions/`. | `<Имя>.json` | `schema-format.md`, 3, 11.1 | `Text.json`, `definitions/TextColor.json` |
| **идентификатор контракта** | Логический путь контракта без корня `contracts/` и без `definitions/`. | `<слой>/<сущность>/<Имя>`; метка `ref` в Figma | `schema-format.md`, 6; `bundle-format.md`, 2 | `components/text/Text` |
| **значение** (вид сущности) | Сущность, которая описывает данные и сама не рисуется: foundation и core. Противоположность — компонент. | — | — (определение здесь) | `Spacing`, `Layout` |
| **компонент** | Сущность слоя `components`, которая наследует базовую модель и рисуется на платформах и в Figma. Компонент в Figma — **Figma-компонент**. | `"extends": "Component"` | `schema-format.md`, 5.2 | `Text`, `Badge` |
| **примитив** | Компонент-примитив: базовый компонент с широким API, над которым строятся пресеты с узким API. Тип данных — **примитивный тип**. | — | `ROADMAP.md`, «Видение» | `Container`, `Text` |
| **примитивный тип** | Встроенный тип данных формата. | `string`, `boolean`, `integer`, `float`, `color`, `payload` | `schema-format.md`, 4.1 | `"type": "string"` |
| **свойство** | Поле контракта. Свойство в Figma пишется **свойство Figma-компонента** или по виду: variant-свойство, text-свойство, boolean-свойство, instance swap-свойство. | `properties` | `schema-format.md`, 5 | `Text.content` |
| **вариант** | Альтернатива `oneOf`, в том числе вариант шкалы в файле значений. Вариант Figma в Component Set — **variant** (латиницей, не склоняется). | `oneOf`, `name` элемента | `schema-format.md`, 7 | `ImageSource.remote`, `Spacing.xs2` |
| **базовая модель** | Контракт `Component`: поля, общие для всех компонентов. | `Component`, `extends` | `schema-format.md`, 5.2; `component-model.md`, 3 | `layout`, `padding`, `appearance` |
| **модель** | Значение компонента, записанное по формату значений: объект с одним ключом — именем компонента. Дерево моделей — экран из вложенных моделей. | `{ "Text": { … } }` | `schema-format.md`, 4.5; `component-model.md` | `{ "Badge": { "content": "none" } }` |
| **контекст оформления** | Набор состояний, которые допускает оформление компонента. | `appearanceContext`; variant-свойства `state`, `selected` | `schema-format.md`, 5.2; `figma-mapping.md`, 3.5 | `control`: `default`, `pressed`, `disabled` |
| **величина** | Конкретное число, цвет или стиль варианта в файле значений; контракт задаёт только имена. | значение ключа в `modes[].values` | `schema-format.md`, 9 | `xs2` = `2` |
| **файл значений** | Величины вариантов контракта по режимам одной темы. | `<Имя>.values.json` | `schema-format.md`, 9.1 | `themes/default/Spacing.values.json` |
| **режим** | Набор величин файла значений; в Figma — mode коллекции переменных. Работа плагина — «две задачи», не режимы; тело и экземпляр — **способ отрисовки**. | `modes`; mode коллекции | `schema-format.md`, 9.1; `figma-mapping.md`, 3.1 | `light`, `dark` |
| **тема** | Каталог файлов значений; бренд переопределяет тему `default`. Режимы лежат внутри её файлов, тема режимом не является. | `themes/<имя>/` | `schema-format.md`, 9.4 | `default` |
| **алиас** | Величина-ссылка на вариант другого контракта. | `{ "$ref": …, "value": … }`; в наборе — `alias` | `schema-format.md`, 9.3 | `ColorRole.primary` → `ColorPalette#gold68` |
| **статус платформы** | Доступность уровня контракта на Android, iOS и в Figma; наследуется вниз. | `releaseVersions`: `released`, `notReleased`, `willNotBeReleased` | `schema-format.md`, 8 | `"figma": "released"` |
| **журнал изменений** | Записи об изменениях API контрактов сущности для дизайнера и плагина. | `changelog.json`; `kind`, `target` | `schema-format.md`, 11.4 | `renamed` `content.symbol` → `content.image` |

## Образцы и документация

| Термин | Определение | В JSON / Figma | Где подробно | Например |
|---|---|---|---|---|
| **образец** | Файл `samples/<имя>.json` сущности — значение публичного контракта; у компонента — модель с конкретными свойствами. `min` и `max` генерируются, именованные пишутся вручную. | `samples/`; `sample` и `variants` в `figma.json` | `schema-format.md`, 11.1, правило 8; `figma-mapping.md`, 6.2 | `Text#priceWithLink` |
| **подсказка `sample`** | Значение, которое генератор образцов подставляет вместо выбора по правилам `min` и `max`. Не значение по умолчанию. | `sample` в контракте | `schema-format.md`, 11.1, правило 8 | `"sample": "m"` |
| **пример** | Пункт секции документации: ссылается на образец (у компонента) или на демонстрацию (у core) и несёт подпись. | `examples[]`: `sample` или `demo`, `caption` | `documentation-manifest.md`, 5 | `{ "id": "count", "sample": "count" }` |
| **демонстрация** | Модель для примера сущности core: показывает её поведение на готовом компоненте. Интерактивный пример в States — «интерактивный прототип Figma». | `demos/<имя>.json`, `demo` | `documentation-manifest.md`, 5.2 | `layout/widthSizing` |
| **демо-экран** | Экран из моделей для проверки отрисовки, импорта и обновления макетов; компонент не документирует. | `screens/<имя>.json` | `bundle-format.md`, 3.9 | `androidMessages` |
| **превью величин** | Отображение величин шкалы на странице Values: шаблон с дыркой `value`. | `preview.json` | `figma-documentation.md`, 5 | превью `Spacing` |
| **элемент оформления** | Шаблон-модель для страниц документации с дырками для данных. | `figma/documentation/elements/`, `holes` | `figma-documentation.md`, 5 | `propertyRow`, `example` |
| **дырка** | Место в элементе оформления, куда плагин подставляет данные. | `holes`, `"$имя"` в `model` | `figma-documentation.md`, 5 | дырка `caption` |
| **манифест документации** | Состав страницы документации сущности: секции и примеры. | `docs.json` | `documentation-manifest.md` | `components/badge/docs.json` |
| **секция** | Часть страницы документации. | `sections[]`, `type` | `documentation-manifest.md`, 4 | `overview`, `variants`, `history` |
| **набор** | Один JSON со всем, что нужно плагину: контракты, величины, образцы, манифесты и т. д. | `build/bundle.json`; `bundleFormat` | `bundle-format.md` | набор с GitHub Pages |

## Figma

| Термин | Определение | В JSON / Figma | Где подробно | Например |
|---|---|---|---|---|
| **Figma-компонент** | Component или Component Set библиотеки, построенный из контракта компонента или описания пресета. Каждый пресет в Figma — Figma-компонент, но не наоборот. | Component, Component Set; метка `ref` | `figma-mapping.md`, 3.2, 11 | `Badge` |
| **variant** | Вариант Figma в Component Set: одно сочетание значений variant-свойств. Латиницей, не склоняется. | variant Component Set | `figma-mapping.md`, 5 | `content=text, state=default` |
| **проект Figma-компонента** | Решение, как контракт ложится в Figma: образцы и переопределения свойств. | `figma.json` | `figma-mapping.md`, 6 | `badge/figma.json` |
| **variant с образцами** | Variant-свойство, у которого каждое значение рисуется своим образцом. | `variants` в `figma.json` | `figma-mapping.md`, 6.2 | `Badge.content` |
| **коллекция режимов компонента** | Коллекция переменных Figma, в которую отображено свойство, меняющее только величины. | `"as": "mode"` | `figma-mapping.md`, 3.3, 4.2 | `components/button/Button#size` |
| **переопределение слоя** | Свойство контракта, которое задаёт свойство слоя внутри Figma-компонента, а не становится свойством Figma-компонента. | `"as": "override"` | `figma-mapping.md`, 4.1, правило 9 | роль типографики `Text` |
| **слой** | Слой Figma. В общем смысле — уровень в стопке отрисовки (`overlay`, тень). Уровень `contracts/` — **слой контрактов**. | node | `figma-mapping.md`, 10 | текстовый слой |
| **место** | Положение слоя в модели, по которому плагин находит его при повторной отрисовке. В пресете — узел модели варианта с `id`: его имя в слое и в swap. | `slot` в `sharedPluginData`; `id` | `figma-mapping.md`, 7, правило 8; 11.1, правило 6 | `children[1]`, `text`, `carrier`; `title` |
| **ядро отрисовки** | Часть плагина, которая строит слои Figma из дерева моделей; ею же рисуются тела Figma-компонентов. | `render.ts` | `figma-mapping.md`, 10 | — |
| **способ отрисовки** | Как ядро рисует компонент: **тело** — слои из модели, **экземпляр** — instance Figma-компонента библиотеки. | — | `figma-mapping.md`, 10.1, правило 1 | `Container` — всегда тело |
| **индикатор** | Маленький компонент у угла формы носителя, отделённый вырезом. | `indicators`, `ComponentIndicator` | `component-model.md`, 12 | точка «в сети» на аватаре |
| **якорь** | Точка угла носителя, к которой привязан индикатор. Фрейм Figma, который держит индикатор, — **фрейм-якорь**. | `anchor`: `topStart`, `topEnd`, `bottomStart`, `bottomEnd` | `component-model.md`, 12 | `topEnd` |
| **фрейм-якорь** | Фрейм Auto Layout 0×0, в котором лежит индикатор: держит его центр на точке угла. | `role: anchor` | `figma-mapping.md`, 10.2, правило 4 | — |
| **сборка** | Построение части библиотеки из набора: `foundation` или `components`; плагин помечает файл, из какого набора она сделана. | `imports` в `figma.root` | `figma-mapping.md`, 7, правило 11 | сборка `components` |
| **чеклист готовности** | Пункты, после которых ставится `figma: released`; в Figma — фрейм Release Checklist. | `figma/releaseChecklist.json` | `figma-mapping.md`, 8; `figma-documentation.md`, 3.5 | пункт 6 |

## Пресеты

| Термин | Определение | В JSON / Figma | Где подробно | Например |
|---|---|---|---|---|
| **пресет** | Типовая композиция примитивов с узким API, которая задаёт ограничения ради единообразия. Живёт только в Figma: на платформе и в SDUI пресета нет — есть примитивы. Не путать со **стилем оформления**. | `figma/presets/<Имя>.json`; Component Set | `figma-mapping.md`, 11 | ячейка списка |
| **описание пресета** | Файл, по которому плагин строит пресет: корень, оси, явный список вариантов пресета, места со swap. Не контракт. | `figma/presets/<Имя>.json`; идентификатор `figma/presets/<Имя>` | `figma-mapping.md`, 11.2 | `figma/presets/ListRow` |
| **вариант пресета** | Элемент явного списка вариантов в описании: значения осей и модель варианта. В Figma — variant Component Set пресета. | `variants[]`, `axes` | `figma-mapping.md`, 11.1, правило 1 | `lines: 2`, `value: trailing` |
| **ось** (пресета) | Variant-свойство Component Set пресета: меняет устройство слоёв самого пресета. | `axes` | `figma-mapping.md`, 11.1, правило 3 | `lines` |
| **модель варианта** | Дерево моделей примитивов и контейнеров одного варианта пресета внутри описания. У пресета образцов нет. | `variants[].model` | `figma-mapping.md`, 11.2, правило 1 | `{ "Container": { … } }` |
| **корень композиции** | Компонент корня модели каждого варианта; определяет, чей это пресет, но не раскладку файлов. | `root` | `figma-mapping.md`, 11.1, правило 9 | картинка в кнопке — пресет `Button` |
| **витрина** | Component Set пресета на холсте целиком, без отбора, разложенный таблицей по осям. | `layout`: `rows`, `columns`, `blocks` | `figma-mapping.md`, 11.1, правило 8 | — |
| **стиль оформления** | Набор значений `appearance` под одним смысловым именем: против повтора полей по состояниям и для вида из темы. Данные модели, а не Figma; ещё не спроектирован. | — | `component-model.md`, 8, правило 8 | — |
