# Отображение контрактов в Figma

**Статус:** Черновик для согласования  
**Версия спецификации:** 0.35

## 1. Назначение

Документ определяет, как сущности, описанные UI-контрактами, представляются в Figma: какой объект Figma соответствует
сущности, как свойства контракта превращаются в свойства Figma-компонента, кто проектирует и кто создаёт эти объекты.

Плагин работает в двух режимах:

| Режим            | Вход                                                 | Результат                                                            |
|------------------|------------------------------------------------------|----------------------------------------------------------------------|
| Библиотека       | Контракты, файлы значений, `figma.json`              | Figma-компоненты, переменные и стили (разделы 3–7).                  |
| Отрисовка модели | Дерево моделей (`specifications/component-model.md`) | Слои макета: фреймы контейнеров и instances компонентов (раздел 10). |

**Figma-компонент** — обобщённое название объекта, в который отображается компонент: обычный Component или Component
Set (раздел 3.2).

Документ не меняет формат контрактов (`schema-format.md`) и не описывает документацию компонентов
(`figma-documentation.md`, `documentation-manifest.md`). Документация использует объекты, созданные по этой
спецификации.

## 2. Ответственность

| Участник               | Ответственность                                                                                                                 |
|------------------------|---------------------------------------------------------------------------------------------------------------------------------|
| UI Contract            | Состав сущности, свойства, варианты, доступность на платформах. Не содержит Figma-специфики.                                    |
| Файл значений          | Величины foundation-сущностей по режимам (`schema-format.md`, раздел 9).                                                        |
| Figma Generation Skill | Подбирает образцы и переопределения свойств Figma-компонента и сохраняет согласованный проект в файл `figma.json`.              |
| Figma Plugin           | Детерминированно создаёт и обновляет объекты Figma из контрактов, файлов значений и `figma.json`; отрисовывает деревья моделей. |

Источник истины — файлы в Git. Плагин не принимает свободные инструкции AI: он строит только то, что описано в
согласованных файлах. Ручные правки созданных плагином объектов могут быть перезаписаны при следующей синхронизации.

## 3. Соответствие сущностей

| Сущность контракта                    | Объект Figma                       | Источник                                                |
|---------------------------------------|------------------------------------|---------------------------------------------------------|
| Foundation-сущность с файлом значений | Коллекция переменных (Variables)   | Контракт, файл значений темы, `figma.json` (раздел 6.3) |
| Компонент                             | Component или Component Set        | Контракт и `figma.json`                                 |
| Контейнер (`Container`)               | Фрейм, только при отрисовке модели | Модель (раздел 10.3)                                    |

### 3.1. Foundation-сущности

1. Каждая foundation-сущность с файлом значений отображается в одну коллекцию переменных Figma. Величины берутся из
   темы `default` (`schema-format.md`, раздел 9.4).
2. Переменные создаются для вариантов из файла значений. Имя переменной строится по правилу `schema-format.md`,
   раздел 10: префикс — имя контракта в `lowerCamelCase` без суффикса `Role`, затем вариант (`spacing/xs2`,
   `color/primary`, `typography/bodyMedium`, `icon/close`). Тот же префикс получают стили и компоненты символов.
   Коллекция называется именем контракта (`Spacing`).
3. Режимы коллекции соответствуют `modes` файла значений; первый режим — режим по умолчанию.
4. Варианты со свойствами (например, `custom`) переменными не являются и не создаются.
5. Тип переменной определяется `valueType`: `color` — COLOR, `integer` и `float` — FLOAT, `string` — STRING,
   `boolean` — BOOLEAN.
6. Алиас (`schema-format.md`, раздел 9.3) становится ссылкой на соответствующую переменную целевой коллекции, а не
   копией величины.
7. Внутренние контракты темы (например, палитра) отображаются в коллекции, скрытые от публикации библиотеки
   (`hiddenFromPublishing`), с пустыми областями применения (`scopes`): они доступны как цели алиасов, но не
   предлагаются дизайнерам напрямую.
8. Токены библиотеки оформления документации (`figma-documentation.md`, раздел 5) отображаются по тем же правилам в
   отдельные коллекции с префиксом `Documentation`, например `Documentation/Spacing`. Имена переменных внутри коллекции
   строятся так же (`spacing/m`).
9. Сущность, величины которой имеют тип `TypographyStyle`, отображается в текстовые стили и коллекцию переменных их
   параметров. Стиль — по одному на вариант, с именем по разделу 10 `schema-format.md` (например,
   `typography/bodyMedium`). Вес шрифта переводится в название начертания Figma (400 — Regular, 500 — Medium,
   700 — Bold). Параметры стиля всегда привязаны к переменным коллекции, названной именем контракта, с режимами файла
   значений — независимо от числа режимов: величины типографики переопределяются темой так же, как цвета, а размер
   символа во фрагменте текста следует за кеглем (раздел 10.5).

   | Переменная                        | Тип    | Поле стиля      | Scopes           | Публикуется |
   |-----------------------------------|--------|-----------------|------------------|-------------|
   | `typography/<роль>/fontSize`      | FLOAT  | `fontSize`      | `FONT_SIZE`      | да          |
   | `typography/<роль>/lineHeight`    | FLOAT  | `lineHeight`    | `LINE_HEIGHT`    | нет         |
   | `typography/<роль>/letterSpacing` | FLOAT  | `letterSpacing` | `LETTER_SPACING` | нет         |
   | `typography/<роль>/fontFamily`    | STRING | `fontFamily`    | `FONT_FAMILY`    | нет         |
   | `typography/<роль>/fontWeight`    | FLOAT  | `fontWeight`    | `FONT_WEIGHT`    | нет         |

   Необязательный `letterSpacing` без величины записывается как 0. `lineHeight` и `letterSpacing` — в пикселях.
10. Сущность, величины которой имеют тип `ElevationStyle`, отображается в стили эффектов и коллекцию переменных их
    параметров. Стиль — по одному на вариант с эффектом Drop shadow (например, `elevation/m`). Параметры эффекта всегда
    привязаны к переменным коллекции, названной именем контракта, с режимами файла значений. Переменные скрыты от
    публикации: дизайнер выбирает стиль эффекта.

    | Переменная                    | Тип   | Поле эффекта | Scopes         |
    |-------------------------------|-------|--------------|----------------|
    | `elevation/<уровень>/offsetX` | FLOAT | `offsetX`    | `EFFECT_FLOAT` |
    | `elevation/<уровень>/offsetY` | FLOAT | `offsetY`    | `EFFECT_FLOAT` |
    | `elevation/<уровень>/blur`    | FLOAT | `radius`     | `EFFECT_FLOAT` |
    | `elevation/<уровень>/spread`  | FLOAT | `spread`     | `EFFECT_FLOAT` |
    | `elevation/<уровень>/color`   | COLOR | `color`      | `EFFECT_COLOR` |

    Необязательный `spread` без величины записывается как 0.
11. Внутренние контракты начертаний шрифтов (например, `FontFace`) в Figma не отображаются: Figma использует шрифты по
    имени семейства и начертанию.
12. Сущность, величины которой имеют тип `IconValue` (символы, `contracts/foundation/icon`), отображается не в
    переменные, а в компоненты библиотеки: по одному компоненту на вариант с именем по разделу 10 `schema-format.md`
    (например, `icon/close`). Компонент содержит вектор из файла SVG темы в собственном размере рисунка; ограничения
    вектора — `Scale`, чтобы рисунок масштабировался вместе с экземпляром. Заливка вектора — чёрная заглушка: цвет
    задаёт место использования переменной роли цвета на экземпляре. Признак `mirrored` в Figma не отображается: макеты
    для письма справа налево не строятся. Если файл значений содержит несколько режимов, используется первый.
    Компоненты символов лежат на странице сущности `Icon` в области `Component` (`figma-documentation.md`, раздел 3).
13. Области применения (`scopes`) и публикацию переменных публичной сущности с примитивным `valueType` задаёт её
    `figma.json` (раздел 6.3): величины одного типа (например, отступы и скругления) имеют разный смысл, и из
    типа он не выводится.
14. Если шрифта стиля нет в Figma, стиль не создаётся и не обновляется, а плагин сообщает о нём; остальные объекты
    строятся.

Foundation-сущности создаются плагином напрямую из контракта и файла значений; проектирование Skill не требуется.

### 3.2. Компоненты

1. Каждый публичный контракт компонента со статусом `figma: released` или `notReleased`, кроме `Container`
   (раздел 3.4), отображается в один Figma-компонент.
2. Вид Figma-компонента определяется вариантами образцов (раздел 6.2) и состояниями оформления (раздел 3.5): если есть
   хотя бы одно variant-свойство — Component Set, иначе — обычный Component.
3. Имя Figma-компонента совпадает с именем контракта (`Button`). Имя является отображаемым атрибутом; объект
   идентифицируется по разделу 7.1.
4. Набор свойств Figma-компонента выводится из контракта по разделу 4.
5. Визуальное устройство — тело образца: модели компонента, отрисованной по разделу 10 (раздел 6).
6. Figma-компоненты лежат на странице `Components` столбиком в порядке имён. Страница хранит в `sharedPluginData`
   (`uiContracts`, ключ `role`) значение `components`; Figma-компоненты идентифицируются по разделу 7.1.

### 3.3. Коллекции режимов компонента

Свойство, отображённое в режим (раздел 4.2), реализуется отдельной коллекцией переменных:

1. Коллекция создаётся для каждого такого свойства и называется `<Компонент>/<свойство>`, например `Button/size`.
2. Режимы коллекции — значения свойства в порядке контракта, с теми же именами; первый режим — режим по умолчанию.
3. Переменные коллекции и их величины по режимам задаёт проект Figma-компонента. Величины, как правило, ссылаются на
   переменные foundation-сущностей. Формат их описания пока не определён (раздел 11), поэтому переопределение `mode`
   компоненты пока не используют.
4. Значение свойства у instance задаётся явным выбором режима этой коллекции.

### 3.4. Контейнер

`Container` не отображается в Figma-компонент: Figma-компонент не может принимать произвольные instances в качестве
детей. Контейнер создаётся только при отрисовке модели — как фрейм (раздел 10.3). Файл `figma.json` для него не
нужен; статус `figma` контракта означает поддержку контейнера при отрисовке.

### 3.5. Состояния оформления

Контексты оформления компонента (`appearanceContext`, `schema-format.md`, раздел 5.2) добавляют variant-свойства
состояний, если оформление образца (раздел 6.2) задаёт эти состояния — `appearance` образца является вариантом
контекста, например `control`. Образец с оформлением `plain` даёт Figma-компонент без свойств состояний: одинаковые
варианты дизайнеру не нужны.

| Контекст     | Variant-свойства    | Значения                                                               |
|--------------|---------------------|------------------------------------------------------------------------|
| `plain`      | нет                 | —                                                                      |
| `control`    | `state`             | `default`, `pressed`, `disabled`                                       |
| `focusable`  | `state`             | `default`, `focused`, `disabled`                                       |
| `selectable` | `selected`, `state` | `selected`: `false`, `true`; `state`: `default`, `pressed`, `disabled` |

1. Свойства состояний участвуют в декартовом произведении вариантов Component Set (раздел 5).
2. Имя `state` зарезервировано: собственное свойство компонента так называться не может.
3. Для `selectable` variant-свойство `selected` — это обязательное свойство `selected` контракта компонента
   (`boolean`), отображённое в variant (раздел 4.1, правило 4).
4. Оформление корня в каждом варианте — оформление образца для этого состояния: вариант рисуется тем же образцом с
   выбранным состоянием.
5. Если контекстов несколько, их свойства и значения объединяются в порядке таблицы. Например, `["plain", "control"]`
   даёт `state` со значениями `default`, `pressed`, `disabled`.

## 4. Отображение свойств

Figma поддерживает четыре вида свойств компонента: variant, boolean, text и instance swap. Кроме того, свойство
контракта может не становиться свойством Figma-компонента, а задавать свойство слоя внутри компонента — переопределение
слоя (`override`, правило 9). Каждое свойство контракта, доступное в Figma (с учётом наследования статусов,
`schema-format.md`, раздел 8.5), отображается по таблице:

| Свойство контракта                                    | Свойство Figma по умолчанию | Допустимое переопределение      |
|-------------------------------------------------------|-----------------------------|---------------------------------|
| `$ref` на `enum`                                      | variant                     | mode, override                  |
| `$ref` на `oneOf`, все доступные варианты без свойств | variant                     | mode, override                  |
| `$ref` на `oneOf` с вариантами со свойствами          | не отображается             | variant (с образцами), override |
| `boolean`                                             | boolean                     | variant                         |
| `string`                                              | text                        | —                               |
| `$ref` на `oneOf` с вариантом типа `string`           | не отображается             | text                            |
| `$ref` на контракт компонента                         | instance swap               | —                               |
| `integer`, `float`                                    | не отображается             | variant (с `values`), override  |
| `$ref` на `object`, не являющийся компонентом         | не отображается             | —                               |

### 4.1. Правила

1. **Значения variant.** Значения variant-свойства — имена значений перечисления или вариантов `oneOf` после
   разворачивания (`schema-format.md`, раздел 7), доступных в Figma, в порядке контракта. Для `boolean`,
   отображённого в variant, значения — `true` и `false`.
2. **Варианты со свойствами.** Вариант `oneOf`, имеющий свойства (например, `custom`), не отображается в значение
   свойства Figma-компонента: числовых свойств у компонентов Figma нет. В образце такой вариант — величина без привязки
   к переменной (например, ширина слоя, заданная числом). Исключение — variant с образцами (раздел 6.2): значение
   variant — имя варианта `oneOf`, его свойства задаёт образец этого значения.
3. **Непредставимые свойства.** Свойство, для которого в таблице указано «не отображается», обязано иметь статус
   `figma: willNotBeReleased`, если `figma.json` не задаёт для него допустимое переопределение (раздел 6.1).
4. **Boolean.** Свойство boolean в Figma может только скрывать или показывать слои. Если значение влияет на
   внешний вид иначе, свойство переопределяется в variant (раздел 6.1).
5. **Необязательные text и instance swap.** Для необязательного (`required: false`) свойства типа `string` или
   ссылки на компонент дополнительно создаётся boolean-свойство видимости с именем `has<Имя>` в `lowerCamelCase`,
   например `hasSubtitle` для `subtitle`.
6. **Имена.** Имена свойств Figma совпадают с именами свойств контракта, за исключением правила 5. Таблица
   переименований не используется.
7. **Отобранные значения.** Variant-свойство может содержать не все значения контракта, а отобранные — частые случаи,
   достаточные для библиотеки. Они задаются полем `values` в `figma.json` (раздел 6.1): подмножество значений
   перечисления или вариантов `oneOf` в порядке контракта либо явные значения `integer` и `float`. Для `integer` и
   `float` поле обязательно. Числа становятся значениями variant в десятичной записи (`1`, `2`).
8. **Необязательные variant-свойства.** Отсутствие значения у необязательного свойства (`required: false`),
   отображённого в variant, становится последним значением variant с именем `none`.
9. **Переопределение слоя.** Свойство с `"as": "override"` не становится свойством Figma-компонента: его значение —
   свойство слоя внутри компонента (например, текстовый стиль или fill текстового слоя). Слой и его свойство
   определяет отрисовка образца (раздел 10). В instance значение меняется обычным переопределением слоя.
10. **Значения вне отобранных.** Свойство с `values` задаёт свойство слоя образца, как при переопределении. При
    отрисовке модели значение, которого нет среди отобранных, задаётся переопределением этого слоя поверх варианта
    `none` (для необязательного свойства) или первого отобранного значения.
11. **Текстовое содержимое.** Свойство-`oneOf` с вариантом типа `string` (например, `Text.content`) может отображаться
    в text-свойство (`"as": "text"`): text-свойство привязано к текстовому слою образца, значение в библиотеке — текст
    образца. Остальные варианты задаются при
    отрисовке модели переопределением текстового слоя; фрагменты текста становятся стилями диапазонов символов
    (`setRangeTextStyleId`, `setRangeFills`, `setRangeTextDecoration`). Нажатия на фрагменты в Figma не отображаются.
    Символы во фрагментах текстовый слой не содержит: такой текст отрисовывается по разделу 10.5.
12. **Источник изображения.** `Image.source` отображается в variant с образцами (раздел 6.2) со значениями `resource`
    и `remote`. В варианте `resource` слой символа — экземпляр компонента символа (раздел 3.1, правило 12) с instance
    swap-свойством `icon`; цвет символа (`resource.icon.color`) — переопределение заливки вектора переменной
    `ColorRole`. В варианте `remote` слой картинки — прямоугольник с заливкой-картинкой; в библиотеке вместо картинки
    по адресу — нейтральная заливка-заглушка. Отрисовка модели — раздел 10.4.
13. **Содержимое бейджа.** `Badge.content` отображается в variant с образцами (раздел 6.2) со значениями `none`,
    `text`, `image`: корень — Auto Layout с минимальной шириной, равной высоте, содержимое по центру. В варианте
    `text` — текстовый слой с text-свойством `text`, роль типографики и цвет — переопределения слоя. В варианте
    `image` — слой символа с instance swap-свойством `icon`, как у `Image` (правило 12); картинка по адресу в бейдже
    рисуется только при отрисовке модели телом. При отрисовке модели вариант выбирается по виду содержимого, значения
    задаются переопределениями слоёв.

### 4.2. Режимы вместо variant

Свойство, значения которого меняют только величины (цвета, отступы, скругления, типографику), но не устройство слоёв,
переопределяется в `mode` (раздел 6.1) и реализуется коллекцией режимов (раздел 3.3), а не variant-свойством.

Skill оставляет variant-свойствами только измерения, меняющие устройство слоёв: состав, видимость частей, направление
компоновки. Это ограничивает число вариантов Component Set (раздел 5).

### 4.3. Свойства базовой модели

Свойства, полученные компонентом от базовой модели (`extends`, `schema-format.md`, раздел 5.2), не отображаются в
свойства Figma-компонента и не подчиняются таблице раздела 4: они задают свойства корневого слоя.

1. В библиотеке величины корня по умолчанию (размеры, отступы, оформление по состояниям) задаёт образец
   (раздел 6.2). Размер в экземпляре дизайнер меняет средствами Figma, в том числе привязкой к переменным `size/…`:
   размер задаёт место использования, а не свойство компонента.
2. При отрисовке модели значения модели применяются к корню instance как переопределения (разделы 10.1, правило 7,
   и 10.2).

## 5. Варианты Component Set

1. Component Set содержит по одному варианту для каждого сочетания значений variant-свойств (полное декартово
   произведение). Свойства, отображённые в режимы, boolean, text и instance swap число вариантов не увеличивают.
2. Варианты идентифицируются сочетанием значений variant-свойств, а не Figma node ID.
3. Значение variant с образцами, для которого образца нет, в Component Set не входит (раздел 6.2).
4. Наличие варианта в Component Set не означает его обязательного показа в документации, и наоборот
   (`figma-documentation.md`, раздел 6).

## 6. Файл проекта Figma-компонента

Файл располагается в каталоге сущности рядом с публичным контрактом и называется `figma.json`. Например,
`button/figma.json`. Файл не является контрактом.

Файл обязателен для каждого компонента, отображаемого в Figma-компонент. Его готовит Skill; содержимое утверждается до
сохранения в Git. Файл foundation-сущности описан в разделе 6.3.

| Поле         | Назначение                                                                   |
|--------------|------------------------------------------------------------------------------|
| `$ref`       | Ссылка на публичный контракт компонента.                                     |
| `sample`     | Образец Figma-компонента без variant с образцами (раздел 6.2).               |
| `variants`   | Variant с образцами: имя свойства → значение variant → образец (раздел 6.2). |
| `iconSample` | Только у `Text`: образец компонента `text/icon` (раздел 10.5).               |
| `properties` | Необязательные переопределения отображения свойств (раздел 6.1).             |

Задаётся ровно одно из полей `sample` и `variants`.

**Пример** — `badge/figma.json`:

```json
{
  "$ref": "Badge",
  "variants": {
    "content": {
      "none": "dot",
      "text": "count",
      "image": "icon"
    }
  }
}
```

### 6.1. Переопределения свойств

1. Ключи `properties` — имена свойств контракта; значения — объекты с полем `as`, задающим вид свойства Figma.
2. Допустимы только переопределения из столбца «Допустимое переопределение» раздела 4.
3. Свойства, не указанные в `properties`, отображаются по умолчанию.
4. Для variant-свойства объект может содержать `values` — отобранные значения (раздел 4.1, правило 7). Набор отбирает
   Skill при проектировании компонента; он утверждается вместе с проектом.
5. Свойство из `variants` в `properties` не указывается: оно отображается в variant с образцами.

### 6.2. Образцы

Образец — именованный пример компонента (`samples/<имя>.json` в каталоге сущности, `schema-format.md`, раздел 11.1);
в файле указывается его имя без расширения. Плагин рисует тело образца по разделу 10 и превращает его в
Figma-компонент или вариант Component Set. Устройство слоёв, величины корня и оформление по состояниям Figma-компонент
получает от образца.

1. Корень образца — модель этого компонента без индикаторов: индикаторы в Figma-компоненты не входят (README
   `Component`, «Индикаторы»).
2. **Variant с образцами** — для свойства, значения которого меняют устройство слоёв и не выводятся из одной модели
   (например, `Badge.content`: пустая точка, текст, символ). Ключ `variants` — имя свойства; значения — имена вариантов
   `oneOf` или перечисления, доступных в Figma, а у необязательного свойства ещё и `none` — отсутствие значения
   (раздел 4.1, правило 8). У образца значения свойство имеет этот вариант, у образца `none` — не задано. Порядок
   значений variant — порядок контракта, `none` последним.
3. `variants` содержит одно свойство. Если образца для значения нет, значение в Component Set не входит.
4. Свойства Figma привязываются к слоям тела по правилам раздела 4.1 (правила 9–13) и раздела 10.5 по месту слоя в
   модели (раздел 7, правило 8): текстовый слой — `text`, символ — `icon`, символы `text/icon` — `leadingIcon` и
   `trailingIcon`. Пути к слоям в файле не указываются. Значение свойства Figma одно на весь Component Set: экземпляр
   показывает его, а не слой своего варианта. Поэтому свойство задаёт первый по порядку вариант с этим слоем; вариант
   с тем же значением привязывается к нему, вариант с другим значением получает своё свойство
   `<имя> (<значения варианта>)`, например `icon (image)`.
5. Значения свойств Figma в библиотеке — значения образца (например, текст text-свойства). Значения по умолчанию в
   контрактах нет (`schema-format.md`, раздел 13), их роль играет образец.

### 6.3. Файл проекта foundation-сущности

Публичная foundation-сущность с примитивным `valueType` — её величины становятся самостоятельными переменными
(раздел 3.1) — имеет `figma.json` рядом с публичным контрактом. Он задаёт то, что не выводится из контракта:

```json
{
  "$ref": "Spacing",
  "scopes": ["GAP"]
}
```

| Поле      | Назначение                                                                                      |
|-----------|-------------------------------------------------------------------------------------------------|
| `$ref`    | Ссылка на публичный контракт сущности.                                                          |
| `scopes`  | Непустой список областей применения переменных (`VariableScope` Figma), допустимых для их типа. |
| `publish` | Необязательный; `false` скрывает переменные от публикации библиотеки. По умолчанию `true`.      |

1. Допустимые `scopes` для переменных COLOR: `ALL_FILLS`, `FRAME_FILL`, `SHAPE_FILL`, `TEXT_FILL`, `STROKE_COLOR`,
   `EFFECT_COLOR`. Для FLOAT: `CORNER_RADIUS`, `WIDTH_HEIGHT`, `GAP`, `STROKE_FLOAT`, `EFFECT_FLOAT`, `OPACITY`,
   `FONT_WEIGHT`, `FONT_SIZE`, `LINE_HEIGHT`, `LETTER_SPACING`, `PARAGRAPH_SPACING`, `PARAGRAPH_INDENT`. Для STRING:
   `TEXT_CONTENT`, `FONT_FAMILY`, `FONT_STYLE`. `ALL_SCOPES` не используется: он предлагает переменную везде.
2. Сущностям с составным `valueType` (`TypographyStyle`, `ElevationStyle`, `IconValue`) файл не нужен: scopes их
   переменных следуют из привязанного поля стиля (раздел 3.1, правила 9 и 10), у символов переменных нет.

## 7. Создание и обновление

1. Плагин создаёт Figma-компонент, если его нет, и обновляет существующий на месте.
2. Плагин не удаляет и не пересоздаёт Figma-компонент и варианты Component Set целиком: пересоздание меняет ключи
   компонентов и разрывает связь с instances в файлах, которые используют библиотеку.
3. При изменении контракта плагин добавляет новые варианты и свойства, обновляет существующие и удаляет только
   варианты и свойства, исчезнувшие из контракта. Так же обновляются переменные, стили и компоненты символов: величины
   меняются на месте, и привязанные к ним слои обновляются без пересборки компонентов. Экземпляры удалённого варианта
   в том же и в других файлах не отвязываются и не переходят на другой вариант: они остаются на удалённом компоненте
   с прежним видом и переопределениями.

   **Переименование значения variant** берётся из журнала изменений сущности: запись `renamed`, у которой `target` и
   `from` — значения одного variant-свойства (`content.symbol` и `content.image`; `schema-format.md`, раздел 11.4).
   Если в наборе есть вариант с прежним значением, а варианта с новым нет, плагин переименовывает вариант на месте.
   Ключ компонента сохраняется, и экземпляры во всех файлах получают новое имя, когда принимают обновление
   библиотеки. Записи применяются от старых к новым; повторный импорт ничего не меняет. Без записи `renamed`
   переименование для экземпляров равносильно удалению варианта и добавлению нового.
4. При синхронизации плагин восстанавливает имена объектов по контрактам и сообщает о расхождениях.
5. Синхронизация документации не затрагивает Figma-компоненты (`figma-documentation.md`, раздел 3).
6. Перед удалением переменной, стиля или компонента символа плагин ищет их использования в текущем файле. Объект
   удаляется в любом случае — источник истины контракт, — а найденные использования перечисляются в отчёте. Так же
   удаляется вариант Component Set: отчёт перечисляет его экземпляры в текущем файле (страница, имя) и предупреждает,
   что в других файлах экземпляры останутся на удалённом компоненте без обновлений. Файлы, подключившие библиотеку,
   плагин не видит: удаление варианта — несовместимое изменение контракта. Что ставить вместо удалённого варианта,
   дизайнеру говорит `description` записи `removed` журнала изменений.
7. Объекты файла без идентификатора плагина (раздел 7.1) не изменяются и не удаляются.
8. Тело образца перерисовывается в существующий Figma-компонент или вариант: слои сопоставляются с прежними по месту в
   модели и обновляются на месте. Место хранится в `sharedPluginData` (`uiContracts`, ключ `slot`): `id` модели, путь
   ребёнка (`children[1]`, `indicators[0]`) или часть тела (`text`, `icon`, `image`, `overlay`, `carrier`);
   пересоздаются только слои, вид которых изменился (например, текст сменился символом). Figma связывает переопределения
   в экземплярах со слоями компонента, поэтому правки дизайнера в макетах переживают пересборку библиотеки.
9. Значение экземпляра, совпавшее со значением Figma-компонента, Figma не закрепляет за экземпляром: после правки
   образца экземпляр берёт новое значение компонента. Поэтому, рисуя экземпляр по модели (раздел 10.1), плагин явно
   задаёт ему instance swap- и boolean-свойства. Text-свойство явно не задаётся: это сбрасывает стили диапазонов
   текста. Текст экземпляра, совпавший с текстом образца, после правки образца меняется вместе с ним.
10. **Переход Component ↔ Component Set** при появлении первого или исчезновении последнего variant-свойства не
    пересоздаёт компонент. Образец компонента и каждого варианта хранится в `sharedPluginData` (`uiContracts`, ключ
    `sample`).
    - **Component → Component Set:** существующий компонент становится вариантом с тем же образцом, без метки
      образца — первым вариантом. Остальные варианты создаются рядом.
    - **Component Set → Component:** из набора выносится вариант с образцом из `sample`, без такого варианта — первый.
      Остальные варианты удаляются по правилу 6.

    Узел остаётся тем же, поэтому ключ компонента сохраняется, а свойства Figma и переопределения экземпляров Figma
    переносит между компонентом и набором сам. Свойства Figma (кроме variant), к которым после обновления не привязан
    ни один слой, плагин удаляет: компонент с такими свойствами Figma не публикует (Unused properties). Они остаются,
    например, после выноса варианта из набора или удаления варианта, который один использовал свойство.

11. **Метка сборки в файле.** После успешной сборки плагин записывает, из какого набора она сделана: в
    `sharedPluginData` корня документа (`figma.root`), пространство `uiContracts`, ключ `imports`. Значение — JSON с
    меткой на каждую из пяти сборок:

    ```json
    {
      "foundation": { "source": { "commit": "abc1234…", "committedAt": "2026-10-20T14:05:00+03:00", "branch": "dev", "dirty": false }, "importedAt": "2026-10-20T11:07:12.000Z" },
      "documentation": { "source": { … }, "importedAt": "…" }
    }
    ```

    Ключи: `foundation`, `components`, `documentation`, `samples`, `screens`. `source` копируется из набора как есть
    (`bundle-format.md`, раздел 3.11), `importedAt` — время сборки в UTC. Кнопки сборки независимы, поэтому файл
    бывает смешанным, и одна метка «последний импорт» врала бы после частичной пересборки.
    - **Запись.** Плагин меняет только ключ своей сборки и не трогает остальные. Сборка, закончившаяся ошибкой,
      метку не меняет; предупреждения в отчёте не мешают. Набор с GitHub и из файла пишутся одинаково.
    - **Чтение.** Отсутствующий ключ, повреждённое значение или метка не по формату читаются как «не строилось».
    - **Показ.** Окно плагина при открытии показывает блок «В файле» — метку каждой сборки — и обновляет его после
      каждой сборки. При открытии плагин в сеть не ходит. После загрузки набора у каждой метки появляется сравнение
      с ним:

      | Пометка           | Условие                                                                   |
      |-------------------|---------------------------------------------------------------------------|
      | «совпадает»       | коммиты равны и ни у одной стороны нет `dirty`                            |
      | «отстаёт»         | коммит сборки старше коммита набора (`committedAt`)                       |
      | «новее набора»    | коммит сборки новее коммита набора (`committedAt`)                        |
      | «нельзя сравнить» | у одной из сторон `dirty`, нет коммита (вне Git) или время коммитов равно |

### 7.1. Идентификация объектов

Объекты Figma, созданные плагином, сопоставляются с файлами репозитория по стабильному логическому идентификатору, а не
по имени. В Git Figma node ID не хранятся: ссылка направлена из Figma в Git.

1. Идентификатор хранится в `sharedPluginData` объекта в пространстве имён `uiContracts` под ключом `ref`.
   `sharedPluginData` используется вместо `pluginData`, чтобы идентификатор не зависел от ID конкретного плагина и был
   доступен другим инструментам.
2. Значение — идентификатор контракта (`schema-format.md`, раздел 6): логический `<слой>/<сущность>/<Имя>` без
   корня `contracts/` и без `definitions/`, у внутреннего контракта темы — путь от корня репозитория без `.json`:

   | Объект                                   | Пример идентификатора                                          |
   |------------------------------------------|----------------------------------------------------------------|
   | Figma-компонент                          | `components/button/Button`                                     |
   | Компонент `text/icon` (раздел 10.5)      | `components/text/Text#icon`                                    |
   | Коллекция переменных foundation-сущности | `foundation/spacing/Spacing`                                   |
   | Коллекция режимов компонента             | `components/button/Button#size`                                |
   | Коллекция внутреннего контракта темы     | `themes/default/ColorPalette`                                  |
   | Переменная, стиль, компонент символа     | `foundation/spacing/Spacing#xs2`                               |
   | Переменная параметра стиля               | `foundation/typographyRole/TypographyRole#bodyMedium/fontSize` |
   | Страница сущности                        | `foundation/icon/Icon`                                         |

   Для коллекции режимов после `#` указывается имя свойства; для переменной, стиля и компонента символа — имя
   варианта, для переменной параметра стиля — ещё и имя параметра после `/`.
3. Объект без идентификатора, созданный до плагина или вручную, привязывается один раз по имени с подтверждением
   пользователя. Далее используется только идентификатор.
4. Идентификатор меняется только при переименовании слоя, сущности или контракта. Раскладка файлов внутри сущности
   (например, перенос в `definitions/`) и имя корня `contracts/` идентификатор не меняют. Плагин обнаруживает
   объекты, идентификаторы которых не соответствуют существующим контрактам, и предлагает перепривязать их.

## 8. Статус `figma` в контракте

### 8.1. Значение

Статус `figma: released` означает, что сущность прошла чеклист этого раздела на сборке из актуальной версии контракта.
Статус проставляется в контракте вручную, через PR.

- **Файл библиотеки.** Пока нет продуктового файла, библиотекой считается тестовый файл библиотеки, потребителем —
  тестовый файл-потребитель. Пункт 15 проверяется на этой паре.
- **Зависимости.** Сущность получает `figma: released` только после того, как его получили все foundation- и
  core-сущности, на которые она ссылается.

### 8.2. Чеклист компонента

Применяется к компоненту с `figma.json`, кроме `Container`.

Автоматические пункты:

1. `validate.py` проходит на сборке импорта.
2. Блок «В файле» показывает «совпадает».
3. Вид, свойства, варианты и режимы соответствуют контракту (раздел 9, пункт 4).
4. Значения привязаны к переменным.
5. Страница документации нарисована, обязательные секции на месте.

Ручные пункты:

6. Варианты Component Set, включая состояния (раздел 3.5), и режимы коллекций компонента (раздел 3.3) правильны в
   светлой теме.
7. То же в тёмной теме.
8. Образцы и примеры читаются: без обрезки, наложений и пустот.
9. Экземпляр из библиотеки переключает свойства и варианты без поломки вида.
10. Ресайз соответствует контракту: hug и fill, min и max, длинный текст, отсутствие картинки.
11. Индикаторы держатся на углах при ресайзе.
12. Компонент собирается в `Container` по правилу «Сборка макетов в Figma».
13. Описание и рекомендации в README понятны без контракта.
14. Таблица свойств совпадает с панелью свойств Figma.
15. Библиотека опубликована, обновление дошло до файла-потребителя.

Пункт 15 ручной: плагин не видит публикацию библиотеки.

### 8.3. Сокращённый чеклист foundation, core и Container

Для foundation- и core-сущностей и `Container` применяются пункты, которые к ним относятся:

- foundation: пункты 1, 2, 3, 5, 6, 7, 15 — пункт 4 не нужен: величины foundation сами являются переменными;
- core: пункты 1, 2, 5, 6, 7, 15 — пункты 3 и 4 не нужны: своих объектов в Figma у core нет;
- `Container`: пункты 1, 2, 5, 6, 7, 8, 10, 12, 13, 15 — пункты 3, 4, 9, 11 и 14 не нужны: `Container` всегда
  рисуется фреймом (раздел 10.3), Figma-компонента и экземпляров у него нет.

### 8.4. Сброс статуса

- Новое свойство или значение получает собственный `figma: notReleased` на своём уровне.
- Ломающее изменение существующего свойства или значения возвращает `figma: notReleased` на уровне контракта в том же
  PR.
- Правки описания, README и образцов статус не меняют.

### 8.5. Данные чеклиста

Пункты записаны в `figma/releaseChecklist.json` и попадают в набор (`bundle-format.md`, раздел 3.12); плагин
показывает их во фрейме Release Checklist (`figma-documentation.md`, раздел 3.5).

```json
{ "items": [ { "number": 1, "kind": "auto", "text": "`validate.py` проходит на сборке импорта.", "appliesTo": ["component", "foundation", "core"] } ] }
```

1. `number` — номер пункта из раздела 8.2, пункты по возрастанию номеров.
2. `kind` — `auto` для автоматических пунктов, `manual` для ручных.
3. `text` — текст пункта из раздела 8.2 в одну строку.
4. `appliesTo` — к чему пункт применим: `component` (раздел 8.2), `foundation`, `core` и `container` (раздел 8.3).

Валидатор сверяет файл с разделами 8.2 и 8.3: номера, вид, тексты и применимость.

## 9. Валидация

Планируемые проверки:

1. Каждое свойство со статусом `figma` отличным от `willNotBeReleased` представимо по разделу 4.
2. Для каждого компонента, отображаемого в Figma-компонент, существует `figma.json` с корректным `$ref`.
3. Переопределения в `properties` ссылаются на существующие свойства и допустимы по разделу 4.
4. Существующий в Figma объект соответствует контракту: вид (Component или Component Set), имена и виды свойств,
   значения variant, полнота вариантов, коллекции режимов и их режимы. Эту проверку выполняет плагин.
5. Идентификаторы объектов в Figma соответствуют существующим контрактам (раздел 7.1). Эту проверку выполняет плагин.
6. Собственные свойства компонентов не используют зарезервированное имя `state` (раздел 3.5).
7. `values` содержит только значения, допустимые контрактом (раздел 4.1, правило 7).
8. У каждой публичной foundation-сущности с примитивным `valueType` есть `figma.json` с корректным `$ref`;
   `scopes` непусты и допустимы для типа переменных (раздел 6.3).
9. Задано ровно одно из полей `sample` и `variants`; образцы существуют, их корень — модель этого компонента без
   индикаторов; значения `variants` допустимы, и образец каждого значения имеет этот вариант свойства (раздел 6.2).

## 10. Отрисовка модели

Плагин строит слои Figma из дерева моделей: значения записаны по `schema-format.md`, раздел 4.5. Режим проверяет ядро
отрисовки и вид SDUI в Figma на моделях из набора: примерах (`samples/`) и демо-экранах (`screens/`).

### 10.1. Общие правила

1. Компонент отрисовывается в одном из двух режимов:
   - **тело** — слои, построенные из модели по разделам 10.2–10.5: корень — фрейм с полями базовой модели, внутри —
     содержимое компонента. Из тела образца строится Figma-компонент библиотеки (раздел 3.2), поэтому библиотека и
     макеты рисуются одной отрисовкой;
   - **instance** — экземпляр Figma-компонента библиотеки, значения задаются его свойствами и переопределениями слоёв
     (правило 7). Режим используется всегда, когда Figma-компонент есть на странице `Components`. Если его нет или
     модель требует того, чего в нём нет (наложение у компонента без слоя наложения, картинка по адресу в `Badge`),
     этот элемент рисуется телом, а плагин сообщает причину (правило 5); об отсутствующем Figma-компоненте — один раз
     за отрисовку. Соседние элементы остаются экземплярами.

   `Container` всегда рисуется телом — фреймом (раздел 10.3).
2. Вариант instance выбирается по значениям variant-свойств модели. Состояния взаимодействия в статичном макете не
   показываются: выбирается `state = default`, для `selectable` — `selected` по значению модели. Модель с
   оформлением `plain` у компонента с несколькими контекстами отрисовывается вариантом `state = default` с
   оформлением `plain`.
3. Значения, ссылающиеся на варианты foundation-сущностей, привязываются к переменным и стилям (раздел 3.1). Варианты со
   свойствами (например, `custom`) задаются числом без привязки. После отрисовки плагин записывает в заливки значение
   переменной цвета для слоя и привязывает её заново: Figma Desktop не пересчитывает значение у текстов и фигур,
   привязанных через API внутри фрейма с явным режимом коллекции, и показывает заглушку.
4. Повторная отрисовка находит слои по месту в модели (`id` модели или путь, раздел 7, правило 8) и обновляет их на
   месте. Экземпляр сохраняет узел; если нужен другой вариант того же Figma-компонента, он переключается
   (`swapComponent`).
5. Значение, которое невозможно отобразить (например, компонент без Figma-компонента), плагин не пропускает молча, а
   сообщает о нём.
6. Значения свойств с переопределением слоя и значения вне отобранных задаются переопределением слоя (раздел 4.1,
   правила 9 и 10).
7. **Значения экземпляра.** Корень экземпляра получает поля базовой модели как переопределения (раздел 4.3, правило 2):
   оформление и ограничения размера образца снимаются и задаются по модели. Текст, стиль и цвет текстового слоя, символы
   и картинка — переопределения слоёв с теми же местами, что в теле (`text`, `icon`, `leadingIcon`, `trailingIcon`,
   `image`, `overlay`). Слои компонента, которых нет в модели (например, символ после текста в `text/icon`),
   скрываются: менять состав и порядок слоёв экземпляра Figma не даёт.

### 10.2. Базовая модель

Поля базовой модели задают свойства корня instance или фрейма контейнера:

| Поле                            | Figma                                                                                                                                                                                                                                                               |
|---------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `id`                            | `sharedPluginData`, пространство имён `uiContracts`, ключ `id`, и имя слоя `<Компонент> · <id>` (без `id` — `<Компонент>`), в том числе экземпляра. У модели с индикаторами так называется носитель; обёртка и `carrier` — нет.                                     |
| `layout.width`, `layout.height` | `layoutSizingHorizontal` / `layoutSizingVertical`: `hug` — HUG, `fill` — FILL, `fixed` — FIXED с размером из `Size`. `min` и `max` — `minWidth`, `maxWidth`, `minHeight`, `maxHeight`.                                                                              |
| `layout.position: flow`         | `layoutPositioning = AUTO`.                                                                                                                                                                                                                                         |
| `layout.position: pinned`       | `layoutPositioning = ABSOLUTE`, констрейнты: `start`/`top` — MIN, `end`/`bottom` — MAX, `center` — CENTER, `stretch` — STRETCH; смещения переводятся в координаты.                                                                                                  |
| `padding`                       | `paddingLeft`, `paddingTop`, `paddingRight`, `paddingBottom`; `start` — left, `end` — right.                                                                                                                                                                        |
| `appearance`                    | Оформление показанного состояния (`plain`, для состояний — вариант по разделу 10.1): fill с цветом `ColorRole`, effect style `Elevation`, `cornerRadius`, stroke inside (`strokeWeight` из `BorderWidth`, цвет `ColorRole`), `clipsContent`, наложение (правило 3). |
| `indicators`                    | Фрейм носителя и индикаторов с маской выреза (правило 4).                                                                                                                                                                                                           |
| `events`                        | Не отображается (`willNotBeReleased`).                                                                                                                                                                                                                              |

1. При `relativeTo: content` плагин прибавляет к смещению `padding` родителя: в Figma абсолютные дети отсчитываются от
   края фрейма. У родителя с раскладкой `overlay` (фрейм без Auto Layout, раздел 10.3) отступы берутся из модели, а не
   из полей фрейма: у такого фрейма поля отступов не действуют.
2. Figma поддерживает только письмо слева направо: `start` всегда соответствует левой стороне.
3. Наложение (`overlay`) — верхний дочерний слой корня: прямоугольник с `layoutPositioning = ABSOLUTE`, констрейнтами
   STRETCH по обеим осям, `cornerRadius` корня и fill с переменной `ColorRole`. Слой виден, только если наложение
   задано, и хранит в `sharedPluginData` (`uiContracts`, ключ `role`) значение `overlay`, чтобы плагин находил его
   при повторной отрисовке. Обводка корня (stroke inside) рисуется поверх детей, поэтому порядок слоёв совпадает с
   платформами. У Figma-компонентов с состояниями слой наложения входит в тело каждого варианта (раздел 3.5,
   правило 4).
4. Индикаторы (`indicators`) строятся только при отрисовке модели. Носитель и его индикаторы оборачиваются фреймом-
   обёрткой с Auto Layout и `clipsContent = false`: обёртка получает `layout` носителя и занимает его место в раскладке
   родителя, а индикаторы выступают за неё, не меняя размер. Слои обёртки снизу вверх:
   - якоря индикаторов с `gap` — под маской: носитель вырезан по форме индикаторов, и они видны сквозь вырез;
   - маска `cutout` (`isMask = true`) — фрейм без обрезки с констрейнтами STRETCH, внутри булева операция Subtract:
     прямоугольник, покрывающий носитель с тенью и обводкой и все индикаторы, минус формы индикаторов с `gap`. Форма
     выреза — размер индикатора и скругление его углов, увеличенное на `gap`, расширенные на `gap` во все стороны.
     Форму носителя маска не повторяет: скругление и `clip` носитель задаёт сам. У булевой операции в Figma нет
     констрейнтов, поэтому маска — фрейм: при изменении размера носителя прямоугольник растягивается, а вырезы едут
     за своими углами;
   - фрейм `carrier` — Auto Layout без обрезки с `layout` носителя, внутри носитель. Маска Figma не режет фрейм с
     `clipsContent = true`, поэтому носитель с `clip` лежит в промежуточном фрейме;
   - якоря индикаторов без `gap` — над носителем.

   Каждый индикатор лежит во фрейме-якоре: Auto Layout размером 0×0 (Figma хранит его как 0.0001) с выравниванием по
   центру по обеим осям, без заливки и обрезки. Якоря и маска лежат в обёртке с `layoutPositioning = ABSOLUTE`. Центр
   якоря — точка угла формы носителя (вершина или середина дуги скругления под 45°); констрейнты якоря и выреза — по
   углу: `end` — MAX, `start` — MIN, `top` — MIN, `bottom` — MAX. Когда содержимое индикатора меняется (например, текст
   бейджа в экземпляре), Auto Layout якоря держит центр индикатора на точке угла; когда растягивается носитель, якорь
   едет за углом. Вырез следует за размером индикатора только при повторной отрисовке: фигуру внутри булевой операции
   нельзя привязать к размеру соседнего слоя, поэтому выросший индикатор расходится с вырезом симметрично. Размеры выреза вычисляются при отрисовке и к переменным не привязываются: у
   переменных Figma нет выражений «скругление + `gap`»; после смены величин нужна повторная отрисовка (раздел 10.1,
   правило 4). Размер обёртки следует за носителем; ручное растяжение обёртки не поддерживается: носитель с `fixed`
   сохраняет размер, а индикаторы и вырезы уходят за углами обёртки.

   Обёртка хранит в `sharedPluginData` (`uiContracts`, ключ `role`) значение `indicators`, фрейм носителя — `carrier`, якорь —
   `anchor`. Обёртка, нарисованная без якорей, при повторной отрисовке переносит индикаторы в якоря с сохранением их
   экземпляров и переопределений. Если маску построить не удалось, индикаторы рисуются поверх носителя без выреза, а плагин сообщает об этом (раздел
   10.1, правило 5).
5. Пустой фрейм с Auto Layout в Figma не сжимается по содержимому. Если у компонента без содержимого размер `hug`,
   плагин задаёт его по этой оси суммой отступов, как на платформах.
6. Текстовый слой `Text` с шириной `hug` без `min` и `max` — HUG с автошириной. Если у корня `hug` задан `min` или
   `max`, текстовый слой — FILL с автовысотой: корень обнимает текст в пределах `minWidth` и `maxWidth`, длинный текст
   переносится. `maxWidth` самого текстового слоя не используется: в экземпляре компонента библиотеки Figma не даёт его
   переопределить, а текст, добавленный во фрейм с `minWidth` или `maxWidth`, Figma и так растягивает.

### 10.3. Контейнер

| Модель                           | Figma                                                                                                                                                   |
|----------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|
| `horizontal`, `vertical`         | `layoutMode = HORIZONTAL` / `VERTICAL`, `layoutWrap = NO_WRAP`.                                                                                         |
| `horizontalWrap`, `verticalWrap` | `layoutMode = HORIZONTAL` / `VERTICAL`, `layoutWrap = WRAP`.                                                                                            |
| `alignment`                      | `counterAxisAlignItems`: `start`/`top` — MIN, `center` — CENTER, `end`/`bottom` — MAX, `baseline` — BASELINE, в том числе с Wrap.                       |
| `distribution: packed`           | `itemSpacing` = `gap`, `primaryAxisAlignItems` по `position`: MIN, CENTER, MAX.                                                                         |
| `distribution: spaceBetween`     | `primaryAxisAlignItems = SPACE_BETWEEN`.                                                                                                                |
| `lineDistribution: packed`       | `counterAxisAlignContent = AUTO`, `counterAxisSpacing` = `gap`.                                                                                         |
| `lineDistribution: spaceBetween` | `counterAxisAlignContent = SPACE_BETWEEN`.                                                                                                              |
| `overlay`                        | `layoutMode = NONE`. Дети с `position = flow` получают констрейнты по `horizontal` и `vertical` (MIN, CENTER, MAX) и координаты, рассчитанные плагином. |
| `children`                       | Дочерние слои в том же порядке; первый ребёнок — нижний слой.                                                                                           |

1. Фрейм контейнера хранит в `sharedPluginData` (`uiContracts`, ключ `ref`) путь к контракту
   `components/container/Container`, чтобы плагин отличал контейнеры от остальных фреймов.
2. `gap` привязывается к переменной `Spacing`, как и `padding`.

### 10.4. Изображение

| Модель               | Figma                                                                                                       |
|----------------------|-------------------------------------------------------------------------------------------------------------|
| `resource.icon`      | `source = resource`; в слое символа — экземпляр `icon/<имя>`, заливка вектора — переменная `ColorRole`.     |
| `remote.origin.url`  | `source = remote`; плагин загружает картинку (`figma.createImageAsync`) и ставит её заливкой слоя картинки. |
| `remote.scale`       | `scaleMode`: `fit` — FIT, `crop` — FILL.                                                                    |
| `remote.alignment`   | При `crop` — смещение через `imageTransform`, рассчитанное плагином; при `fit` — то же для полей.           |
| `remote.placeholder` | Не отображается: макет показывает загруженную картинку.                                                     |
| `remote.error`       | Если загрузка не удалась — в теле слой символа с ресурсом `error` (иначе `placeholder`).                    |

1. Если загрузка не удалась и ни `error`, ни `placeholder` не заданы, слой картинки остаётся с заглушкой, а плагин
   сообщает об ошибке (раздел 10.1, правило 5). В экземпляре варианта `remote` слоя символа нет: остаётся нейтральная
   заливка компонента.
2. Ресурсы `placeholder` и `error` показываются в собственном размере по центру, символ `resource.icon` при размерах
   `fixed` и `fill` вписывается в слой с сохранением пропорций.
3. Картинка по адресу при размере `hug` показывается в собственном размере. Если у оси `hug` задан `min` или `max`,
   слой картинки растягивается по этой оси, а корень обнимает собственный размер картинки в пределах `min` и `max`
   отдельно по каждой оси; картинка вписывается в получившийся размер по `scale` и `alignment`.
4. Адрес с хостом в зарезервированном домене `.invalid` (RFC 2606), например `https://cdn.example.invalid/items/42.jpg`,
   — заведомо недоступная картинка. Плагин её не загружает и ведёт себя как при неудачной загрузке (правило 1 и строка
   `remote.error`), но без сообщения. Такой адрес показывает `error` или `placeholder` в примерах и образцах; любой
   другой адрес, который не загрузился, по-прежнему даёт сообщение (раздел 10.1, правило 5).

### 10.5. Текст с символами

Текстовый слой Figma не содержит векторов, поэтому для текста с символами по краям библиотека содержит отдельный
компонент `text/icon`, создаваемый вместе с компонентами библиотеки (раздел 3.2) из образца `iconSample` в
`text/figma.json` (раздел 6). Это фрейм с Auto Layout в строку из трёх слоёв: символ до текста, текстовый слой, символ
после текста. В режиме тела (раздел 10.1, правило 1)
`Text` рисуется той же строкой: корень — фрейм с полями базовой модели, символы — экземпляры `icon/<имя>`.

| Свойство компонента           | Figma                                                                                           |
|-------------------------------|-------------------------------------------------------------------------------------------------|
| `text`                        | text-свойство текстового слоя.                                                                  |
| `leading`, `trailing`         | boolean-свойства видимости символа до и после текста.                                           |
| `leadingIcon`, `trailingIcon` | instance swap-свойства символов, значения — компоненты `icon/<имя>`.                            |
| Типографика и цвет текста     | Переопределения текстового слоя: текстовый стиль `typography/…`, fill с переменной цвета.       |
| Цвет символа                  | Переопределение заливки вектора переменной `ColorRole`, как у `Image` (раздел 4.1, правило 12). |

1. **Выбор формы.** При отрисовке модели `Text` становится экземпляром `text/icon`, если содержимое — `rich`, фрагменты
   `icon` стоят только первым и (или) последним, а остальные фрагменты — `text`. Текстовые фрагменты задаются стилями
   диапазонов текстового слоя (раздел 4.1, правило 11), поля базовой модели — свойствами корня экземпляра
   (раздел 10.2). Иначе `Text` отрисовывается текстовым слоем, символ в середине фразы заменяется пробелом, а плагин
   сообщает о приближении (раздел 10.1, правило 5).
2. **Размер символа** равен кеглю роли типографики фрагмента или `Text`: ширина и высота экземпляра символа привязаны к
   переменной `typography/<роль>/fontSize` этой роли (раздел 3.1, правило 9).
3. **Перенос строк.** Символы прижаты к первой строке (`counterAxisAlignItems = MIN`); символ после текста стоит справа
   от всего блока, а не после последнего слова.
4. **Обрезка.** Многоточие ставится только в текстовом слое, символы по краям видны всегда. На платформах символ при
   обрезке — неделимый знак и уходит за многоточие вместе с текстом. Расхождение допустимо: макет показывает
   приближение.

## 11. Открытые вопросы

1. Исключение недопустимых сочетаний variant-свойств: в контрактах пока нет ограничений между свойствами.
2. Variant с образцами по нескольким свойствам (раздел 6.2, правило 3) и формат переменных коллекций режимов
   (раздел 3.3).
3. Отображение составных типов и вложенных `object`, не являющихся компонентами.
4. Слоты: компоненты со свойством типа «любой компонент», кроме контейнера (например, карточка с содержимым), и
   слоты Figma (SlotNode) для них.
5. Отображение foundation-сущностей без файла значений и переменных нечисловых типов.
6. Представление тем помимо `default` в Figma: режимы коллекций или отдельные библиотеки продуктов с переменными тех
   же имён (этап 4 `ROADMAP.md`). Число режимов коллекции ограничено тарифом Figma: двум режимам темы `default`
   (`light`, `dark`) нужен платный тариф, например Professional.
7. Состояние `disabled` при отрисовке модели: выбор по полю компонента, задающему недоступность; такие поля пока не
   согласованы.
