# Отображение контрактов в Figma

**Статус:** Черновик для согласования  
**Версия спецификации:** 0.17

## 1. Назначение

Документ определяет, как сущности, описанные UI-контрактами, представляются в Figma: какой объект Figma соответствует
сущности, как свойства контракта превращаются в свойства Figma-компонента, кто проектирует и кто создаёт эти объекты.

Плагин работает в двух режимах:

| Режим            | Вход                                                 | Результат                                                            |
|------------------|------------------------------------------------------|----------------------------------------------------------------------|
| Библиотека       | Контракты, файлы значений, `<Имя>.figma.json`        | Figma-компоненты, переменные и стили (разделы 3–7).                  |
| Отрисовка модели | Дерево моделей (`specifications/component-model.md`) | Слои макета: фреймы контейнеров и instances компонентов (раздел 10). |

**Figma-компонент** — обобщённое название объекта, в который отображается компонент: обычный Component или Component
Set (раздел 3.2).

Документ не меняет формат контрактов (`schema-format.md`) и не описывает документацию компонентов
(`figma-documentation.md`, `documentation-manifest.md`). Документация использует объекты, созданные по этой
спецификации.

## 2. Ответственность

| Участник               | Ответственность                                                                                                                       |
|------------------------|---------------------------------------------------------------------------------------------------------------------------------------|
| UI Contract            | Состав сущности, свойства, варианты, доступность на платформах. Не содержит Figma-специфики.                                          |
| Файл значений          | Величины foundation-сущностей по режимам (`schema-format.md`, раздел 9).                                                              |
| Figma Generation Skill | Проектирует Figma-компонент по контракту и сохраняет согласованный проект в файл `<Имя>.figma.json`.                                  |
| Figma Plugin           | Детерминированно создаёт и обновляет объекты Figma из контрактов, файлов значений и `<Имя>.figma.json`; отрисовывает деревья моделей. |

Источник истины — файлы в Git. Плагин не принимает свободные инструкции AI: он строит только то, что описано в
согласованных файлах. Ручные правки созданных плагином объектов могут быть перезаписаны при следующей синхронизации.

## 3. Соответствие сущностей

| Сущность контракта                    | Объект Figma                       | Источник                                                      |
|---------------------------------------|------------------------------------|---------------------------------------------------------------|
| Foundation-сущность с файлом значений | Коллекция переменных (Variables)   | Контракт, файл значений темы, `<Имя>.figma.json` (раздел 6.3) |
| Компонент                             | Component или Component Set        | Контракт и `<Имя>.figma.json`                                 |
| Контейнер (`Container`)               | Фрейм, только при отрисовке модели | Модель (раздел 10.3)                                          |

### 3.1. Foundation-сущности

1. Каждая foundation-сущность с файлом значений отображается в одну коллекцию переменных Figma. Величины берутся из
   темы `default` (`schema-format.md`, раздел 9.4).
2. Переменные создаются для вариантов из файла значений. Имя переменной строится по правилу `schema-format.md`,
   раздел 10: префикс — имя контракта в `lowerCamelCase` без суффикса `Role`, затем вариант (`spacing/xs2`,
   `color/primary`, `typography/bodyMedium`, `icon/close`). Тот же префикс получают стили и компоненты символов.
   Коллекция называется именем контракта (`Spacing`).
3. Режимы коллекции соответствуют `modes` файла значений; первый режим — режим по умолчанию.
4. Варианты со свойствами (например, `custom`) переменными не являются и не создаются.
5. Тип переменной определяется `valueType`: `color` — COLOR, `integer` и `float` — FLOAT, `string` — STRING,
   `boolean` — BOOLEAN.
6. Алиас (`schema-format.md`, раздел 9.3) становится ссылкой на соответствующую переменную целевой коллекции, а не
   копией величины.
7. Внутренние контракты темы (например, палитра) отображаются в коллекции, скрытые от публикации библиотеки
   (`hiddenFromPublishing`), с пустыми областями применения (`scopes`): они доступны как цели алиасов, но не
   предлагаются дизайнерам напрямую.
8. Токены библиотеки оформления документации (`figma-documentation.md`, раздел 5) отображаются по тем же правилам в
   отдельные коллекции с префиксом `Documentation`, например `Documentation/Spacing`. Имена переменных внутри коллекции
   строятся так же (`spacing/m`).
9. Сущность, величины которой имеют тип `TypographyStyle`, отображается в текстовые стили и коллекцию переменных их
   параметров. Стиль — по одному на вариант, с именем по разделу 10 `schema-format.md` (например,
   `typography/bodyMedium`). Вес шрифта переводится в название начертания Figma (400 — Regular, 500 — Medium,
   700 — Bold). Параметры стиля всегда привязаны к переменным коллекции, названной именем контракта, с режимами файла
   значений — независимо от числа режимов: величины типографики переопределяются темой так же, как цвета, а размер
   символа во фрагменте текста следует за кеглем (раздел 10.5).

   | Переменная                        | Тип    | Поле стиля      | Scopes           | Публикуется |
   |-----------------------------------|--------|-----------------|------------------|-------------|
   | `typography/<роль>/fontSize`      | FLOAT  | `fontSize`      | `FONT_SIZE`      | да          |
   | `typography/<роль>/lineHeight`    | FLOAT  | `lineHeight`    | `LINE_HEIGHT`    | нет         |
   | `typography/<роль>/letterSpacing` | FLOAT  | `letterSpacing` | `LETTER_SPACING` | нет         |
   | `typography/<роль>/fontFamily`    | STRING | `fontFamily`    | `FONT_FAMILY`    | нет         |
   | `typography/<роль>/fontWeight`    | FLOAT  | `fontWeight`    | `FONT_WEIGHT`    | нет         |

   Необязательный `letterSpacing` без величины записывается как 0. `lineHeight` и `letterSpacing` — в пикселях.
10. Сущность, величины которой имеют тип `ElevationStyle`, отображается в стили эффектов и коллекцию переменных их
    параметров. Стиль — по одному на вариант с эффектом Drop shadow (например, `elevation/m`). Параметры эффекта всегда
    привязаны к переменным коллекции, названной именем контракта, с режимами файла значений. Переменные скрыты от
    публикации: дизайнер выбирает стиль эффекта.

    | Переменная                    | Тип   | Поле эффекта | Scopes         |
    |-------------------------------|-------|--------------|----------------|
    | `elevation/<уровень>/offsetX` | FLOAT | `offsetX`    | `EFFECT_FLOAT` |
    | `elevation/<уровень>/offsetY` | FLOAT | `offsetY`    | `EFFECT_FLOAT` |
    | `elevation/<уровень>/blur`    | FLOAT | `radius`     | `EFFECT_FLOAT` |
    | `elevation/<уровень>/spread`  | FLOAT | `spread`     | `EFFECT_FLOAT` |
    | `elevation/<уровень>/color`   | COLOR | `color`      | `EFFECT_COLOR` |

    Необязательный `spread` без величины записывается как 0.
11. Внутренние контракты начертаний шрифтов (например, `FontFace`) в Figma не отображаются: Figma использует шрифты по
    имени семейства и начертанию.
12. Сущность, величины которой имеют тип `IconValue` (символы, `schemas/foundation/icon`), отображается не в
    переменные, а в компоненты библиотеки: по одному компоненту на вариант с именем по разделу 10 `schema-format.md`
    (например, `icon/close`). Компонент содержит вектор из файла SVG темы в собственном размере рисунка; ограничения
    вектора — `Scale`, чтобы рисунок масштабировался вместе с экземпляром. Заливка вектора — чёрная заглушка: цвет
    задаёт место использования переменной роли цвета на экземпляре. Признак `mirrored` в Figma не отображается: макеты
    для письма справа налево не строятся. Если файл значений содержит несколько режимов, используется первый.
    Компоненты символов лежат на странице сущности `Icon` в области `Component` (`figma-documentation.md`, раздел 3).
13. Области применения (`scopes`) и публикацию переменных публичной сущности с примитивным `valueType` задаёт её
    `<Имя>.figma.json` (раздел 6.3): величины одного типа (например, отступы и скругления) имеют разный смысл, и из
    типа он не выводится.
14. Если шрифта стиля нет в Figma, стиль не создаётся и не обновляется, а плагин сообщает о нём; остальные объекты
    строятся.

Foundation-сущности создаются плагином напрямую из контракта и файла значений; проектирование Skill не требуется.

### 3.2. Компоненты

1. Каждый публичный контракт компонента со статусом `figma: released` или `notReleased`, кроме `Container`
   (раздел 3.4), отображается в один Figma-компонент.
2. Вид Figma-компонента определяется результатом отображения свойств (раздел 4) и состояниями оформления
   (раздел 3.5): если есть хотя бы одно variant-свойство — Component Set, иначе — обычный Component.
3. Имя Figma-компонента совпадает с именем контракта (`Button`). Имя является отображаемым атрибутом; объект
   идентифицируется по разделу 7.1.
4. Набор свойств Figma-компонента выводится из контракта по разделу 4.
5. Визуальное устройство описывается в `<Имя>.figma.json` (раздел 6).

### 3.3. Коллекции режимов компонента

Свойство, отображённое в режим (раздел 4.2), реализуется отдельной коллекцией переменных:

1. Коллекция создаётся для каждого такого свойства и называется `<Компонент>/<свойство>`, например `Button/size`.
2. Режимы коллекции — значения свойства в порядке контракта, с теми же именами; первый режим — режим по умолчанию.
3. Переменные коллекции и их величины по режимам задаёт проект Figma-компонента (раздел 6.2). Величины, как правило,
   ссылаются на переменные foundation-сущностей.
4. Значение свойства у instance задаётся явным выбором режима этой коллекции.

### 3.4. Контейнер

`Container` не отображается в Figma-компонент: Figma-компонент не может принимать произвольные instances в качестве
детей. Контейнер создаётся только при отрисовке модели — как фрейм (раздел 10.3). Файл `<Имя>.figma.json` для него не
нужен; статус `figma` контракта означает поддержку контейнера при отрисовке.

### 3.5. Состояния оформления

Контексты оформления компонента (`appearanceContext`, `schema-format.md`, раздел 5.2) добавляют variant-свойства
состояний:

| Контекст     | Variant-свойства    | Значения                                                               |
|--------------|---------------------|------------------------------------------------------------------------|
| `plain`      | нет                 | —                                                                      |
| `control`    | `state`             | `default`, `pressed`, `disabled`                                       |
| `focusable`  | `state`             | `default`, `focused`, `disabled`                                       |
| `selectable` | `selected`, `state` | `selected`: `false`, `true`; `state`: `default`, `pressed`, `disabled` |

1. Свойства состояний участвуют в декартовом произведении вариантов Component Set (раздел 5).
2. Имя `state` зарезервировано: собственное свойство компонента так называться не может.
3. Для `selectable` variant-свойство `selected` — это обязательное свойство `selected` контракта компонента
   (`boolean`), отображённое в variant (раздел 4.1, правило 4).
4. Оформление корня в каждом варианте — оформление компонента по умолчанию для этого состояния. Его задаёт
   `structure` (раздел 6.2).
5. Если контекстов несколько, их свойства и значения объединяются в порядке таблицы. Например, `["plain", "control"]`
   даёт `state` со значениями `default`, `pressed`, `disabled`.

## 4. Отображение свойств

Figma поддерживает четыре вида свойств компонента: variant, boolean, text и instance swap. Кроме того, свойство
контракта может не становиться свойством Figma-компонента, а задавать свойство слоя внутри компонента — переопределение
слоя (`override`, правило 9). Каждое свойство контракта, доступное в Figma (с учётом наследования статусов,
`schema-format.md`, раздел 8.5), отображается по таблице:

| Свойство контракта                                    | Свойство Figma по умолчанию | Допустимое переопределение     |
|-------------------------------------------------------|-----------------------------|--------------------------------|
| `$ref` на `enum`                                      | variant                     | mode, override                 |
| `$ref` на `oneOf`, все доступные варианты без свойств | variant                     | mode, override                 |
| `boolean`                                             | boolean                     | variant                        |
| `string`                                              | text                        | —                              |
| `$ref` на `oneOf` с вариантом типа `string`           | не отображается             | text                           |
| `$ref` на контракт компонента                         | instance swap               | —                              |
| `integer`, `float`                                    | не отображается             | variant (с `values`), override |
| `$ref` на `object`, не являющийся компонентом         | не отображается             | —                              |

### 4.1. Правила

1. **Значения variant.** Значения variant-свойства — имена значений перечисления или вариантов `oneOf` после
   разворачивания (`schema-format.md`, раздел 7), доступных в Figma, в порядке контракта. Для `boolean`,
   отображённого в variant, значения — `true` и `false`.
2. **Варианты со свойствами.** Вариант `oneOf`, имеющий свойства (например, `custom`), не отображается в значение
   свойства Figma-компонента: числовых свойств у компонентов Figma нет. Внутри `structure` такой вариант используется
   как величина без привязки к переменной (например, ширина слоя, заданная числом). Если свойство компонента
   принимает такой вариант, в Figma он недоступен как значение этого свойства.
3. **Непредставимые свойства.** Свойство, для которого в таблице указано «не отображается», обязано иметь статус
   `figma: willNotBeReleased`, если `<Имя>.figma.json` не задаёт для него допустимое переопределение (раздел 6.1).
4. **Boolean.** Свойство boolean в Figma может только скрывать или показывать слои. Если значение влияет на
   внешний вид иначе, свойство переопределяется в variant (раздел 6.1).
5. **Необязательные text и instance swap.** Для необязательного (`required: false`) свойства типа `string` или
   ссылки на компонент дополнительно создаётся boolean-свойство видимости с именем `has<Имя>` в `lowerCamelCase`,
   например `hasSubtitle` для `subtitle`.
6. **Имена.** Имена свойств Figma совпадают с именами свойств контракта, за исключением правила 5. Таблица
   переименований не используется.
7. **Отобранные значения.** Variant-свойство может содержать не все значения контракта, а отобранные — частые случаи,
   достаточные для библиотеки. Они задаются полем `values` в `<Имя>.figma.json` (раздел 6.1): подмножество значений
   перечисления или вариантов `oneOf` в порядке контракта либо явные значения `integer` и `float`. Для `integer` и
   `float` поле обязательно. Числа становятся значениями variant в десятичной записи (`1`, `2`).
8. **Необязательные variant-свойства.** Отсутствие значения у необязательного свойства (`required: false`),
   отображённого в variant, становится последним значением variant с именем `none`.
9. **Переопределение слоя.** Свойство с `"as": "override"` не становится свойством Figma-компонента: его значение —
   свойство слоя внутри компонента (например, текстовый стиль или fill текстового слоя). Слой и его свойство задаёт
   `structure` (раздел 6.2). В instance значение меняется обычным переопределением слоя.
10. **Значения вне отобранных.** Свойство с `values` привязывается в `structure` к свойству слоя, как при
    переопределении. При отрисовке модели значение, которого нет среди отобранных, задаётся переопределением этого слоя
    поверх варианта `none` (для необязательного свойства) или первого отобранного значения.
11. **Текстовое содержимое.** Свойство-`oneOf` с вариантом типа `string` (например, `Text.content`) может отображаться
    в text-свойство (`"as": "text"`): в библиотеке значение — строка этого варианта. Остальные варианты задаются при
    отрисовке модели переопределением текстового слоя; фрагменты текста становятся стилями диапазонов символов
    (`setRangeTextStyleId`, `setRangeFills`, `setRangeTextDecoration`). Нажатия на фрагменты в Figma не отображаются.
    Символы во фрагментах текстовый слой не содержит: такой текст отрисовывается по разделу 10.5.
12. **Источник изображения.** `Image.source` отображается особо: Figma-компонент `Image` содержит слой символа —
    экземпляр компонента символа (раздел 3.1, правило 12) с instance swap-свойством `icon` — и слой картинки —
    прямоугольник с заливкой-картинкой. Boolean-свойство `remote` показывает слой картинки вместо слоя символа. В
    библиотеке слой картинки содержит нейтральную заливку-заглушку. Цвет символа (`resource.icon.color`) —
    переопределение заливки вектора переменной `ColorRole`. Отрисовка модели — раздел 10.4.
13. **Содержимое бейджа.** `Badge.content` отображается в variant-свойство `content` со значениями `none`, `text`,
    `image`: корень — Auto Layout с минимальной шириной, равной высоте, содержимое по центру. В варианте `text` —
    текстовый слой с text-свойством `text`, роль типографики и цвет — переопределения слоя. В варианте `image` — слои
    символа и картинки, как у `Image` (правило 12), с instance swap-свойством `icon` и boolean-свойством `remote`.
    При отрисовке модели вариант выбирается по виду содержимого, значения задаются переопределениями слоёв.

### 4.2. Режимы вместо variant

Свойство, значения которого меняют только величины (цвета, отступы, скругления, типографику), но не устройство слоёв,
переопределяется в `mode` (раздел 6.1) и реализуется коллекцией режимов (раздел 3.3), а не variant-свойством.

Skill оставляет variant-свойствами только измерения, меняющие устройство слоёв: состав, видимость частей, направление
компоновки. Это ограничивает число вариантов Component Set (раздел 5).

### 4.3. Свойства базовой модели

Свойства, полученные компонентом от базовой модели (`extends`, `schema-format.md`, раздел 5.2), не отображаются в
свойства Figma-компонента и не подчиняются таблице раздела 4: они задают свойства корневого слоя.

1. В библиотеке величины корня по умолчанию (размеры, отступы, оформление по состояниям) задаёт `structure`
   (раздел 6.2).
2. При отрисовке модели значения модели применяются к корню instance как переопределения (раздел 10.2).

## 5. Варианты Component Set

1. Component Set содержит по одному варианту для каждого сочетания значений variant-свойств (полное декартово
   произведение). Свойства, отображённые в режимы, boolean, text и instance swap число вариантов не увеличивают.
2. Варианты идентифицируются сочетанием значений variant-свойств, а не Figma node ID.
3. Наличие варианта в Component Set не означает его обязательного показа в документации, и наоборот
   (`figma-documentation.md`, раздел 6).

## 6. Файл проекта Figma-компонента

Файл располагается в каталоге сущности рядом с публичным контрактом и называется `<Имя>.figma.json`. Например,
`button/Button.figma.json`. Файл не является контрактом.

Файл обязателен для каждого компонента, отображаемого в Figma-компонент. Его готовит Skill; содержимое утверждается до
сохранения в Git. Файл foundation-сущности описан в разделе 6.3.

| Поле         | Назначение                                                                                     |
|--------------|------------------------------------------------------------------------------------------------|
| `$ref`       | Ссылка на публичный контракт компонента.                                                       |
| `properties` | Необязательные переопределения отображения свойств (раздел 6.1).                               |
| `structure`  | Визуальное устройство: слои, Auto Layout, привязки к переменным, переменные коллекций режимов. |

**Пример:**

```json
{
  "$ref": "Button",
  "properties": {
    "isLoading": {
      "as": "variant"
    },
    "size": {
      "as": "mode"
    }
  },
  "structure": {}
}
```

**Важно:** `Button`, `isLoading` и `size` вымышлены; это иллюстрация формата.

### 6.1. Переопределения свойств

1. Ключи `properties` — имена свойств контракта; значения — объекты с полем `as`, задающим вид свойства Figma.
2. Допустимы только переопределения из столбца «Допустимое переопределение» раздела 4.
3. Свойства, не указанные в `properties`, отображаются по умолчанию.
4. Для variant-свойства объект может содержать `values` — отобранные значения (раздел 4.1, правило 7). Набор отбирает
   Skill при проектировании компонента; он утверждается вместе с проектом.

### 6.2. Структура

Формат `structure` пока не определён. Он должен позволять описать слои вариантов, Auto Layout, привязку размеров и
цветов к переменным foundation-сущностей (раздел 3.1), переменные коллекций режимов и их величины по режимам
(раздел 3.3), не используя Figma node ID.

### 6.3. Файл проекта foundation-сущности

Публичная foundation-сущность с примитивным `valueType` — её величины становятся самостоятельными переменными
(раздел 3.1) — имеет `<Имя>.figma.json` рядом с публичным контрактом. Он задаёт то, что не выводится из контракта:

```json
{
  "$ref": "Spacing",
  "scopes": ["GAP"]
}
```

| Поле      | Назначение                                                                                      |
|-----------|-------------------------------------------------------------------------------------------------|
| `$ref`    | Ссылка на публичный контракт сущности.                                                          |
| `scopes`  | Непустой список областей применения переменных (`VariableScope` Figma), допустимых для их типа. |
| `publish` | Необязательный; `false` скрывает переменные от публикации библиотеки. По умолчанию `true`.      |

1. Допустимые `scopes` для переменных COLOR: `ALL_FILLS`, `FRAME_FILL`, `SHAPE_FILL`, `TEXT_FILL`, `STROKE_COLOR`,
   `EFFECT_COLOR`. Для FLOAT: `CORNER_RADIUS`, `WIDTH_HEIGHT`, `GAP`, `STROKE_FLOAT`, `EFFECT_FLOAT`, `OPACITY`,
   `FONT_WEIGHT`, `FONT_SIZE`, `LINE_HEIGHT`, `LETTER_SPACING`, `PARAGRAPH_SPACING`, `PARAGRAPH_INDENT`. Для STRING:
   `TEXT_CONTENT`, `FONT_FAMILY`, `FONT_STYLE`. `ALL_SCOPES` не используется: он предлагает переменную везде.
2. Сущностям с составным `valueType` (`TypographyStyle`, `ElevationStyle`, `IconValue`) файл не нужен: scopes их
   переменных следуют из привязанного поля стиля (раздел 3.1, правила 9 и 10), у символов переменных нет.

## 7. Создание и обновление

1. Плагин создаёт Figma-компонент, если его нет, и обновляет существующий на месте.
2. Плагин не удаляет и не пересоздаёт Figma-компонент и варианты Component Set целиком: пересоздание меняет ключи
   компонентов и разрывает связь с instances в файлах, которые используют библиотеку.
3. При изменении контракта плагин добавляет новые варианты и свойства, обновляет существующие и удаляет только
   варианты и свойства, исчезнувшие из контракта. Так же обновляются переменные, стили и компоненты символов: величины
   меняются на месте, и привязанные к ним слои обновляются без пересборки компонентов.
4. При синхронизации плагин восстанавливает имена объектов по контрактам и сообщает о расхождениях.
5. Синхронизация документации не затрагивает Figma-компоненты (`figma-documentation.md`, раздел 3).
6. Перед удалением переменной, стиля или компонента символа плагин ищет их использования в текущем файле. Объект
   удаляется в любом случае — источник истины контракт, — а найденные использования перечисляются в отчёте. Файлы,
   подключившие библиотеку, плагин не видит: удаление варианта — несовместимое изменение контракта.
7. Объекты файла без идентификатора плагина (раздел 7.1) не изменяются и не удаляются.

### 7.1. Идентификация объектов

Объекты Figma, созданные плагином, сопоставляются с файлами репозитория по стабильному логическому идентификатору, а не
по имени. В Git Figma node ID не хранятся: ссылка направлена из Figma в Git.

1. Идентификатор хранится в `sharedPluginData` объекта в пространстве имён `uiContracts` под ключом `ref`.
   `sharedPluginData` используется вместо `pluginData`, чтобы идентификатор не зависел от ID конкретного плагина и был
   доступен другим инструментам.
2. Значение — путь к публичному контракту от корня репозитория без расширения `.json`:

   | Объект                                   | Пример идентификатора                                                  |
   |------------------------------------------|------------------------------------------------------------------------|
   | Figma-компонент                          | `schemas/components/button/Button`                                     |
   | Коллекция переменных foundation-сущности | `schemas/foundation/spacing/Spacing`                                   |
   | Коллекция режимов компонента             | `schemas/components/button/Button#size`                                |
   | Коллекция токенов документации           | `figma/documentation/tokens/spacing/Spacing`                           |
   | Коллекция внутреннего контракта темы     | `themes/default/ColorPalette`                                          |
   | Переменная, стиль, компонент символа     | `schemas/foundation/spacing/Spacing#xs2`                               |
   | Переменная параметра стиля               | `schemas/foundation/typographyRole/TypographyRole#bodyMedium/fontSize` |
   | Страница сущности                        | `schemas/foundation/icon/Icon`                                         |

   Для коллекции режимов после `#` указывается имя свойства; для переменной, стиля и компонента символа — имя
   варианта, для переменной параметра стиля — ещё и имя параметра после `/`.
3. Объект без идентификатора, созданный до плагина или вручную, привязывается один раз по имени с подтверждением
   пользователя. Далее используется только идентификатор.
4. Перенос или переименование каталога контракта меняет идентификатор. Плагин обнаруживает объекты, идентификаторы
   которых не соответствуют существующим контрактам, и предлагает перепривязать их.

## 8. Статус `figma` в контракте

Статус `figma: released` означает, что объект Figma создан плагином по актуальной версии контракта и опубликован в
библиотеке. Статус проставляется в контракте вручную после публикации.

## 9. Валидация

Планируемые проверки:

1. Каждое свойство со статусом `figma` отличным от `willNotBeReleased` представимо по разделу 4.
2. Для каждого компонента, отображаемого в Figma-компонент, существует `<Имя>.figma.json` с корректным `$ref`.
3. Переопределения в `properties` ссылаются на существующие свойства и допустимы по разделу 4.
4. Существующий в Figma объект соответствует контракту: вид (Component или Component Set), имена и виды свойств,
   значения variant, полнота вариантов, коллекции режимов и их режимы. Эту проверку выполняет плагин.
5. Идентификаторы объектов в Figma соответствуют существующим контрактам (раздел 7.1). Эту проверку выполняет плагин.
6. Собственные свойства компонентов не используют зарезервированное имя `state` (раздел 3.5).
7. `values` содержит только значения, допустимые контрактом; свойства с `values` и с переопределением слоя привязаны к
   слоям в `structure` (раздел 4.1, правила 7–10).
8. У каждой публичной foundation-сущности с примитивным `valueType` есть `<Имя>.figma.json` с корректным `$ref`;
   `scopes` непусты и допустимы для типа переменных (раздел 6.3).

## 10. Отрисовка модели

Плагин строит слои Figma из дерева моделей: значения записаны по `schema-format.md`, раздел 4.5. Режим используется для
проверки моделей сервера и приложений в макете и для сборки макетов из готовых моделей.

### 10.1. Общие правила

1. Компонент отрисовывается в одном из двух режимов:
   - **тело** — слои, построенные из модели по разделам 10.2–10.5: корень — фрейм с полями базовой модели, внутри —
     содержимое компонента. Из тела образца строится Figma-компонент библиотеки (раздел 3.2), поэтому библиотека и
     макеты рисуются одной отрисовкой;
   - **instance** — экземпляр Figma-компонента библиотеки, значения задаются его свойствами и переопределениями слоёв.
     Если Figma-компонента нет, рисуется тело, а плагин сообщает об этом (правило 5).

   `Container` всегда рисуется телом — фреймом (раздел 10.3).
2. Вариант instance выбирается по значениям variant-свойств модели. Состояния взаимодействия в статичном макете не
   показываются: выбирается `state = default`, для `selectable` — `selected` по значению модели. Модель с
   оформлением `plain` у компонента с несколькими контекстами отрисовывается вариантом `state = default` с
   оформлением `plain`.
3. Значения, ссылающиеся на варианты foundation-сущностей, привязываются к переменным и стилям (раздел 3.1). Варианты со
   свойствами (например, `custom`) задаются числом без привязки.
4. Повторная отрисовка находит слои по `id` модели и обновляет их на месте; слои без `id` пересоздаются.
5. Значение, которое невозможно отобразить (например, компонент без Figma-компонента), плагин не пропускает молча, а
   сообщает о нём.
6. Значения свойств с переопределением слоя и значения вне отобранных задаются переопределением слоя (раздел 4.1,
   правила 9 и 10).

### 10.2. Базовая модель

Поля базовой модели задают свойства корня instance или фрейма контейнера:

| Поле                            | Figma                                                                                                                                                                                                                                                               |
|---------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `id`                            | `sharedPluginData`, пространство имён `uiContracts`, ключ `id`. Дизайнер его не видит.                                                                                                                                                                              |
| `layout.width`, `layout.height` | `layoutSizingHorizontal` / `layoutSizingVertical`: `hug` — HUG, `fill` — FILL, `fixed` — FIXED с размером из `Size`. `min` и `max` — `minWidth`, `maxWidth`, `minHeight`, `maxHeight`.                                                                              |
| `layout.position: flow`         | `layoutPositioning = AUTO`.                                                                                                                                                                                                                                         |
| `layout.position: pinned`       | `layoutPositioning = ABSOLUTE`, констрейнты: `start`/`top` — MIN, `end`/`bottom` — MAX, `center` — CENTER, `stretch` — STRETCH; смещения переводятся в координаты.                                                                                                  |
| `padding`                       | `paddingLeft`, `paddingTop`, `paddingRight`, `paddingBottom`; `start` — left, `end` — right.                                                                                                                                                                        |
| `appearance`                    | Оформление показанного состояния (`plain`, для состояний — вариант по разделу 10.1): fill с цветом `ColorRole`, effect style `Elevation`, `cornerRadius`, stroke inside (`strokeWeight` из `BorderWidth`, цвет `ColorRole`), `clipsContent`, наложение (правило 3). |
| `indicators`                    | Фрейм носителя и индикаторов с маской выреза (правило 4).                                                                                                                                                                                                           |
| `events`                        | Не отображается (`willNotBeReleased`).                                                                                                                                                                                                                              |

1. При `relativeTo: content` плагин прибавляет к смещению `padding` родителя: в Figma абсолютные дети отсчитываются от
   края фрейма.
2. Figma поддерживает только письмо слева направо: `start` всегда соответствует левой стороне.
3. Наложение (`overlay`) — верхний дочерний слой корня: прямоугольник с `layoutPositioning = ABSOLUTE`, констрейнтами
   STRETCH по обеим осям, `cornerRadius` корня и fill с переменной `ColorRole`. Слой виден, только если наложение
   задано, и хранит в `sharedPluginData` (`uiContracts`, ключ `role`) значение `overlay`, чтобы плагин находил его
   при повторной отрисовке. Обводка корня (stroke inside) рисуется поверх детей, поэтому порядок слоёв совпадает с
   платформами. У Figma-компонентов с состояниями слой наложения входит в `structure` каждого варианта (раздел 3.5,
   правило 4).
4. Индикаторы (`indicators`) строятся только при отрисовке модели. Носитель и его индикаторы оборачиваются фреймом без
   Auto Layout размером с носитель и с `clipsContent = false`: фрейм занимает место носителя в раскладке родителя
   (получает его `layout`, раздел 10.2), а индикаторы выступают за него, не меняя размер. Внутри фрейма:
   - группа выреза: снизу маска (`isMask = true`) — вектор, построенный плагином операцией Subtract: форма носителя
     минус формы индикаторов с заданным `gap`, расширенные на `gap`; над маской — носитель;
   - над группой — индикаторы в порядке массива: маска действует только на слои своей группы, поэтому индикаторы не
     обрезаются. Центр индикатора — точка угла формы носителя (вершина или середина дуги скругления).

   Фрейм хранит в `sharedPluginData` (`uiContracts`, ключ `role`) значение `indicators`. Если маску построить не
   удалось, индикаторы рисуются без выреза, а плагин сообщает об этом (раздел 10.1, правило 5).
5. Пустой фрейм с Auto Layout в Figma не сжимается по содержимому. Если у компонента без содержимого размер `hug`,
   плагин задаёт его по этой оси суммой отступов, как на платформах.

### 10.3. Контейнер

| Модель                           | Figma                                                                                                                                                   |
|----------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|
| `horizontal`, `vertical`         | `layoutMode = HORIZONTAL` / `VERTICAL`, `layoutWrap = NO_WRAP`.                                                                                         |
| `horizontalWrap`, `verticalWrap` | `layoutMode = HORIZONTAL` / `VERTICAL`, `layoutWrap = WRAP`.                                                                                            |
| `alignment`                      | `counterAxisAlignItems`: `start`/`top` — MIN, `center` — CENTER, `end`/`bottom` — MAX, `baseline` — BASELINE, в том числе с Wrap.                       |
| `distribution: packed`           | `itemSpacing` = `gap`, `primaryAxisAlignItems` по `position`: MIN, CENTER, MAX.                                                                         |
| `distribution: spaceBetween`     | `primaryAxisAlignItems = SPACE_BETWEEN`.                                                                                                                |
| `lineDistribution: packed`       | `counterAxisAlignContent = AUTO`, `counterAxisSpacing` = `gap`.                                                                                         |
| `lineDistribution: spaceBetween` | `counterAxisAlignContent = SPACE_BETWEEN`.                                                                                                              |
| `overlay`                        | `layoutMode = NONE`. Дети с `position = flow` получают констрейнты по `horizontal` и `vertical` (MIN, CENTER, MAX) и координаты, рассчитанные плагином. |
| `children`                       | Дочерние слои в том же порядке; первый ребёнок — нижний слой.                                                                                           |

1. Фрейм контейнера хранит в `sharedPluginData` (`uiContracts`, ключ `ref`) путь к контракту
   `schemas/components/container/Container`, чтобы плагин отличал контейнеры от остальных фреймов.
2. `gap` привязывается к переменной `Spacing`, как и `padding`.

### 10.4. Изображение

| Модель                      | Figma                                                                                                     |
|-----------------------------|-----------------------------------------------------------------------------------------------------------|
| `resource.icon`             | `remote = false`; в слое символа — экземпляр `icon/<имя>`, заливка вектора — переменная `ColorRole`.      |
| `remote.origin.url`         | `remote = true`; плагин загружает картинку (`figma.createImageAsync`) и ставит её заливкой слоя картинки. |
| `remote.scale`              | `scaleMode`: `fit` — FIT, `crop` — FILL.                                                                  |
| `remote.alignment`          | При `crop` — смещение через `imageTransform`, рассчитанное плагином; при `fit` — то же для полей.         |
| `remote.placeholder`        | Не отображается: макет показывает загруженную картинку.                                                   |
| `remote.error`              | Если загрузка не удалась — `remote = false`, в слое символа ресурс `error` (иначе `placeholder`).         |

1. Если загрузка не удалась и ни `error`, ни `placeholder` не заданы, слой картинки остаётся с заглушкой, а плагин
   сообщает об ошибке (раздел 10.1, правило 5).
2. Ресурсы `placeholder` и `error` показываются в собственном размере по центру, символ `resource.icon` при размерах
   `fixed` и `fill` вписывается в слой с сохранением пропорций.

### 10.5. Текст с символами

Текстовый слой Figma не содержит векторов, поэтому для текста с символами по краям библиотека содержит отдельный
компонент `text/icon`, создаваемый вместе с компонентами библиотеки (раздел 3.2). Это фрейм с Auto Layout в
строку из трёх слоёв: символ до текста, текстовый слой, символ после текста. В режиме тела (раздел 10.1, правило 1)
`Text` рисуется той же строкой: корень — фрейм с полями базовой модели, символы — экземпляры `icon/<имя>`.

| Свойство компонента           | Figma                                                                                           |
|-------------------------------|-------------------------------------------------------------------------------------------------|
| `text`                        | text-свойство текстового слоя.                                                                  |
| `leading`, `trailing`         | boolean-свойства видимости символа до и после текста.                                           |
| `leadingIcon`, `trailingIcon` | instance swap-свойства символов, значения — компоненты `icon/<имя>`.                            |
| Типографика и цвет текста     | Переопределения текстового слоя: текстовый стиль `typography/…`, fill с переменной цвета.       |
| Цвет символа                  | Переопределение заливки вектора переменной `ColorRole`, как у `Image` (раздел 4.1, правило 12). |

1. **Выбор формы.** При отрисовке модели `Text` становится экземпляром `text/icon`, если содержимое — `rich`, фрагменты
   `icon` стоят только первым и (или) последним, а остальные фрагменты — `text`. Текстовые фрагменты задаются стилями
   диапазонов текстового слоя (раздел 4.1, правило 11), поля базовой модели — свойствами корня экземпляра
   (раздел 10.2). Иначе `Text` отрисовывается текстовым слоем, символ в середине фразы заменяется пробелом, а плагин
   сообщает о приближении (раздел 10.1, правило 5).
2. **Размер символа** равен кеглю роли типографики фрагмента или `Text`: ширина и высота экземпляра символа привязаны к
   переменной `typography/<роль>/fontSize` этой роли (раздел 3.1, правило 9).
3. **Перенос строк.** Символы прижаты к первой строке (`counterAxisAlignItems = MIN`); символ после текста стоит справа
   от всего блока, а не после последнего слова.
4. **Обрезка.** Многоточие ставится только в текстовом слое, символы по краям видны всегда. На платформах символ при
   обрезке — неделимый знак и уходит за многоточие вместе с текстом. Расхождение допустимо: макет показывает
   приближение.

## 11. Открытые вопросы

1. Формат `structure` в `<Имя>.figma.json`.
2. Исключение недопустимых сочетаний variant-свойств: в контрактах пока нет ограничений между свойствами.
3. Значения по умолчанию свойств Figma и вариант по умолчанию: в контрактах пока нет значений по умолчанию
   (`schema-format.md`, раздел 13).
4. Отбор значений variant и генерация вариантов Component Set для набора компонентов: отдельная задача (скрипт,
   использующий Figma Generation Skill).
5. Отображение составных типов и вложенных `object`, не являющихся компонентами.
6. Слоты: компоненты со свойством типа «любой компонент», кроме контейнера (например, карточка с содержимым), и
   слоты Figma (SlotNode) для них.
7. Отображение foundation-сущностей без файла значений и переменных нечисловых типов.
8. Переход между Component и Component Set при появлении первого или исчезновении последнего variant-свойства без
   потери связи с instances. Сохранение связи при обратном переходе (Component Set → Component) требует проверки.
9. Представление тем помимо `default` в Figma: режимы коллекций или отдельные библиотеки продуктов с переменными тех
   же имён (этап 3 `ROADMAP.md`). Число режимов коллекции ограничено тарифом Figma: двум режимам темы `default`
   (`light`, `dark`) нужен платный тариф, например Professional.
10. Состояние `disabled` при отрисовке модели: выбор по полю компонента, задающему недоступность; такие поля пока не
    согласованы.
