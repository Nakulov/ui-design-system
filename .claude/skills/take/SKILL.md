# Задача в работу

## Ход работы

1. **Задача.** `gh issue view <N> --comments`. Если в «Решении» или «Открытых вопросах» есть нерешённое, что влияет на
   работу, — обсуди с пользователем до начала изменений.
2. **Ветка.** От актуального `dev`: `git switch dev && git pull --ff-only && git switch -c task/<N>-<slug>`, где
   `<slug>` — 1–3 слова латиницей через дефис. Поставь задаче статус In progress функцией `board_status` из скилла
   `groom` (раздел «Доска»).
3. **Изменения.** Делай то, что записано в «Решении» и «Объёме изменений», по правилам `contract-authoring` и
   спецификаций. Изменения вне задачи не вноси — предложи отдельную задачу.
4. **Решения по ходу.** Если в работе пришлось решить то, чего нет в задаче, или отступить от неё, — согласуй с
   пользователем и запиши комментарием в задачу: `gh issue comment <N> --body …`.
5. **Roadmap.** Если задача меняет статус слоя в разделе «Где мы сейчас» `ROADMAP.md` (что есть, чего нет, ссылки на
   задачи), обнови таблицу в том же PR.
6. **Проверка.** Если менялись контракты или примеры, запусти `python3 tools/sync.py`: он генерирует
   `samples/min.json` и `samples/max.json`, обновляет блоки примеров в README и список контрактов в
   `.idea/jsonSchemas.xml`. Затем
   `python3 tools/validate.py --base origin/dev` без ошибок; пройди «Критерии готовности» задачи и
   отметь выполненные в теле задачи.
7. **Проверка в Figma.** Если задача меняет плагин или то, что он рисует (контракты, примеры, тему), пересобери набор
   (`python3 tools/bundle.py`) и плагин (`npm run build` в `figma-plugin/`) и дай пользователю сценарий проверки: что
   открыть, что нажать, что должно получиться. Figma Desktop запускает пользователь.
   - Временные проверки делай только временными именованными примерами (`samples/<случай>.json`). `min.json` и
     `max.json` вручную не правь: `bundle.py` запускает `validate.py`, а он сверяет их с генерацией. Если пример
     встроен в README, синхронизируй README временно (`sync.py`) и откати его вместе с примером до коммита.
   - Расхождения с живым Figma записывай в `figma-mapping` в том же PR.
8. **Коммиты.** Покажи пользователю итог и получи согласие на коммит. Сообщение — на английском, в стиле истории
   репозитория (заголовок, пустая строка, пункты).
9. **PR.** `git push -u origin HEAD`, затем `gh pr create --base dev` по шаблону `.github/pull_request_template.md`:
   `Closes #<N>`, изменения, отклонения от задачи, проверки. Поставь задаче статус In review (`board_status`) и дай ссылку на PR.
10. **Замечания к PR** исправляй новыми коммитами в ту же ветку. Сливает пользователь (squash); после слияния
   переключись на `dev` и обнови его.

## Границы

- В `dev` напрямую не коммить и не пушь: ветка защищена, изменения только через PR.
- Не сливай PR и не закрывай задачу сам.
