# Заготовки для нового компонента или пресета

Заготовки разделов «Объём изменений» и «Критерии готовности» — готовый Markdown для тела задачи. Вставь заготовку и
подгони под компонент: пункты «если …» оставь только при выполненном условии, пункты в квадратных скобках заполни по
«Решению».

- То, что проверяет `validate.py` (файлы каталога, разделы README, сверка `min`/`max`, структура описания пресета),
  не повторяется: его закрывает первый критерий.
- Пункт ссылается на правило с названием раздела, а не пересказывает его: нумерация пунктов в `contract-authoring`
  своя в каждом разделе.
- Выпуск в Figma (`figma: released`, чеклист `figma-mapping.md` §8.2) — решение пользователя: в заготовки не входит.

## Примитив

```markdown
## Объём изменений

- `contracts/components/<сущность>/`: главный контракт и `definitions/`; README — содержание «Рекомендаций по
  использованию» (`contract-authoring`, «Подготовка JSON-контрактов» п. 11) и «Вариантов»; `figma.json` (там же
  п. 10); `docs.json`; `changelog.json` с записью `added`; `samples/` — именованные образцы по сценариям, `min`/`max`
  генерирует `sync.py`.
- Если нужны новые величины — foundation и тема `default`.
- Если компонент вводит новое правило модели — раздел `component-model.md`, версия.
- Если отображение не ложится в существующие правила — `figma-mapping.md`, версия.
- Если меняются и формат (спецификация, валидатор), и плагин — два PR по `groom` п. 6.
- Если появились новые термины — `specifications/glossary.md`.
- `ROADMAP.md`, «Где мы сейчас», строка «Компоненты».

## Критерии готовности

- [ ] `python3 tools/validate.py` проходит.
- [ ] [Поведение из «Решения» — по пункту на правило.]
- [ ] Именованные образцы покрывают сценарии: [список].
- [ ] `min` и `max` — осмысленные модели, без заглушек (`contract-authoring`, «Подготовка JSON-контрактов» п. 12).
- [ ] Новые контракты — `releaseVersions` `notReleased` (`contract-authoring`, «Подготовка JSON-контрактов» п. 4).
- [ ] Проверка в Figma (`take` п. 7), Claude через MCP, затем пользователь: импорт набора, компонент в библиотеке,
  образцы и страница документации отрисованы.
- [ ] Новые термины — в глоссарии.
- [ ] Строка ROADMAP обновлена.
```

## Пресет

Своего контракта, README, журнала и статуса `figma` у пресета нет (`figma-mapping.md` §11.1 правило 10). Если корня
или части нет в системе — отдельная задача на компонент, не эта (`contract-authoring`, «Пресеты» п. 3); зависимость
пишется строкой «Зависит от #N» в «Решении», а не критерием.

```markdown
## Объём изменений

- `figma/presets/<Имя>.json` (`figma-mapping.md` §11.2).
- Если вариантов много — генератор в `tools/presets.py` (§11.2 правило 6).
- Если показывать не все варианты — `examples` для фрейма Presets на странице корня (§11.2 правило 7).
- Если формат пресета не выражает нужное — §11 и валидатор, версия; если меняется и плагин — два PR по `groom` п. 6.
- Если появились новые термины — `specifications/glossary.md`.
- `ROADMAP.md`, «Где мы сейчас», строка «Компоненты».

## Критерии готовности

- [ ] `python3 tools/validate.py` проходит.
- [ ] Варианты, оси, раскладка витрины, места и swap — как в «Решении» (`contract-authoring`, «Пресеты» п. 4).
- [ ] Проверка в Figma (`take` п. 7), Claude через MCP, затем пользователь: после «Построить компоненты» Component Set
  на странице Presets; витрина по `layout`; экземпляры с `id` выставлены наружу; swap предлагает значения `swaps`;
  фрейм Presets на странице корня показывает примеры; длинный текст в экземпляре ведёт себя как в «Решении».
- [ ] Пользователь просмотрел витрину: сочетания осмысленны (`figma-mapping.md` §11.1 правило 8).
- [ ] Новые термины — в глоссарии.
- [ ] Строка ROADMAP обновлена.
```
